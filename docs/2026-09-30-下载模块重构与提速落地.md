# 下载模块重构与提速落地说明（2026-09-30）

> 对应需求：参照 `references/PCL-main` 优化启动器下载——所有「发起下载」的类收进
> `com.example.starlight.download` 并按 engine/source/task/mod 分模块；所有提速能力
> 放进 `download.mod`；官方服务器仅检查更新、安装包下载优先 Gitee 镜像。

## 一、背景与事故记录

- 本轮任务由 OrganizerAgent 分派执行，过程中发生**全量源码损坏事故**：
  批量替换脚本（PowerShell 单元素嵌套数组被 foreach 展开为标量）把 `src/main/java`
  下几乎所有 java 文件的字符 `i` 误替换为 `m`（`import` → `mmport`），278 个文件损坏。
- 恢复手段：`git checkout` 恢复已跟踪文件；6 个不在 git 中的用户历史文件
  （日志上传改造、Java 下载改造的成果）从 `target/gluonfx` 打包产物 `classes.jar`
  反编译完整恢复（LogUploadRecord、LogUploadResultWindow、JavaEnvironmentManager、
  LogUploadStore、DesktopOpener、sendlogs.deleteLog）。
- 损坏现场备份保留在 `backup_broken_20260929/`，确认无需要后可删除。
- 教训：**批量替换一律使用 Python 脚本且先做 pattern 校验**，不再用 PowerShell 数组展开。

## 三、提速能力落地与接线

| 能力 | 实现位置 | 状态 |
|---|---|---|
| 多线程分块 + 动态再分裂 | mod/DownloadPiece + DownloadFileTask | 已实现 |
| 多源候选与切换链 | mod/DownloadSourceChain（fromProvider 注入镜像候选） | 已实现 |
| 全局调度 / 任务队列 | mod/DownloadCoordinator（单例，线程数取 DownloadSettings） | 已实现 |
| 限速（令牌桶 + 低限加速） | mod/GlobalSpeedLimiter | 已实现 |
| 重试 / 熔断 | mod/RetryPolicy + engine/MirrorCircuitBreaker | 已实现 |
| 文件校验 | mod/FileVerifier（大小 + MD5/SHA1） | 已实现 |
| 本地复用 / 元数据缓存 | mod/LocalFileReuse + MetaDiskCache | 已实现 |

**接线点**：`DownloadService.downloadFileAsync(url, savePath, ...)` 已切换为 mod 链路——
多源链（官方 URL + provider 镜像候选）→ DownloadFileTask → DownloadCoordinator.submit
→ 轮询进度直至成功/失败（30 分钟超时保护）。旧 HttpDownloadEngine 单 URL 路径保留在
engine 包，供版本/资产体系（迁移期）继续使用。

`DownloadProviderHolder` 收敛了原先分散在 GameResourceCompleter / LoaderInstallEngine /
VersionDownloadService 等处的 provider 静态持有。

## 四、下载源切换（官方检查 + Gitee 优先）

- `util/UpdateChecker`：官方服务器仅返回版本信息；`attachPreferredMirror` 将安装包直链
  替换为 **Gitee 优先**、GitHub 备用的镜像地址（版本号一致 + 有 .exe 附件才替换），
  镜像不可用时保留官方直链兜底；`UpdateResult.downloadSourceLabel` 记录实际下载源。
- `newui/update/UpdateCoordinator`：`sourceHint` 展示「官方检查 + 镜像下载」提示。
- 说明文档：`docs/2026-09-29-更新下载源切换Gitee镜像.md`。
