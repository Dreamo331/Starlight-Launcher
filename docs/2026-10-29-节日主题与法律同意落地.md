## 二、节日主题：两个独立的问题

### 2.1 「保存不了」的根因：配置键没登记

`ConfigManager.saveClientConfig` 是**读-改-写**，但只回写 `CLIENT_KEYS` 白名单里的键：

```java
Map<String, String> merged = readClientConfig();
for (String key : CLIENT_KEYS) {
    if (config.containsKey(key)) merged.put(key, config.get(key));
}
// 写文件时也只遍历 CLIENT_KEYS
```

`FestivalTheme` 不在白名单 → `ThemePage` 里 `config().put(...) + saveConfig()` 写得进内存缓存、写不进
`starlight-client.ini`，重启后 `getOrDefault("FestivalTheme", "auto")` 又回到默认开启。
修复：在 `CLIENT_KEYS` 登记 `FestivalTheme`（`main/ConfigManager.java`），并补注释说明这类键漏登记的后果。

> 这是一类可复现的坑，已写进根目录 `AGENTS.md` 第七节「设置项落盘」一行。

### 2.2 「背景未加」的根因：`resources/wallpaper/` 是空的

`LauncherView.applyFestivalWallpaper` 按 `/wallpaper/<id>.png|jpg|jpeg|webp` 找图，
找不到就 `return`（保持默认渐变）——代码路径本身正确，但仓库里**一张壁纸都没有**，于是所有节日都「没有背景」。

修复分两层：

1. **补齐资源**：`src/main/resources/wallpaper/<id>.jpg`，11 个 id 与 `FestivalCalendar` 一一对应：
   `chunjie` / `yuanxiao` / `qingming` / `duanwu` / `qixi` / `zhongqiu` / `chongyang` / `guoqing` /
   `wansheng` / `shengdan` / `yuandan`，1600×900 JPEG（约 100–200 KB/张）。
   生成器：`tools/wallpaper-gen/generate_festival_wallpapers.py`（Pillow + numpy，种子固定，可复现）。
   每张都是同一套配方：深色渐变天空 → 柔光/散景 → 节日意象剪影（灯笼、月亮、烟花、松树、南瓜、竹叶…）→ 暗角 → 细颗粒，
   构图刻意把主体放在四角与上下边缘，中央留干净的渐变给卡片与文字。
2. **兜底**：`applyFestivalWallpaper` 找不到资源或解码失败时，按该节日的 `gradientA/B` 画一层对角渐变
   （`applyFestivalGradient`），不再静默不变——避免以后新增节日时又出现「只有问候语变了」。

### 2.3 即时生效与优先级

- `LauncherContext.applyFestivalTheme()`：设置页开关变化 → 先写配置并 `saveConfig()`，再重挂装饰。
  `LauncherView` 持有 `festivalBackdrop` / `festivalScrim` / `festivalTopLayer` 三个节点引用，重建前先整组摘除
  （`clearFestivalDecorations`），所以反复切换不会叠出多套灯笼或壁纸。
- 背景优先级（高 → 低）：**用户壁纸 `BackgroundImage` > 自定义背景色 `CustomThemeColor` > 节日壁纸 > 主题渐变**。
  前两者生效时不铺节日壁纸，只保留灯笼与问候语。
- 可读性遮罩：深色主题 `rgba(0,0,0,0.30)`；浅色主题 `rgba(255,255,255,0.38)`。浅色主题提高到 0.38 是因为
  节日壁纸整体偏暗，18% 白膜下深灰正文对比度不足；0.38 能把壁纸压成「淡彩背景」而不糊掉意象。
- 灯笼层仍是 `FestivalDecorations.topOverlay(...)`，鼠标穿透，不挡点击。

## 三、法律文档告知—同意

### 3.1 流程位置：主界面与后台服务之前

`JavaFXLauncher.start` 的顺序改为：

```
AppFonts.install → checkRuntimeEnvironment → 语言（Language）→
[无有效同意记录] → LegalConsentGate.show(primaryStage, 回调)
[已有有效记录]   → continueStartup(primaryStage)
```

同意页**复用主窗口**并在回调里继续启动，而不是弹出独立 Stage 后 `showAndWait`：
关掉唯一的窗口会触发 JavaFX 的隐式退出，把启动器一起结束。既然是「进入功能之前」的门，
同意之前**不会**执行 `runBackgroundInit`（插件 API 服务、插件子进程、静默登录等都不启动）。

### 3.2 文本从 `docs/` 来，不在仓库里存第二份

单 EXE 不随包分发 `docs/` 目录，所以文本必须进 classpath。做法是 **Maven 构建期复制**，不是提交副本：

```xml
<!-- pom.xml：process-resources -->
<execution>
  <id>copy-legal-docs</id>
  <phase>process-resources</phase>
  <goal>copy-resources</goal>
  <outputDirectory>${project.build.outputDirectory}/legal</outputDirectory>
  <resource><directory>${project.basedir}/docs</directory>
    <includes>免责声明.md / 用户服务协议.md / 隐私政策.md</includes></resource>
</execution>
```

- 唯一真源仍是 `docs/*.md`（符合 `AGENTS.md` 的「法律条款」真源约定）；
- native-image 的 `resourcesList` 已加上 `md` 后缀，否则 EXE 里读不到；
- 资源名保留中文（与 docs 一致）：已实测 `getResourceAsStream("/legal/用户服务协议.md")`
  在**目录**与 **jar** 两种形态下都能读到，无需 ASCII 改名。

### 3.3 同意记录：字段、有效性、撤回

代码：`src/main/java/com/example/starlight/legal/`

| 类 | 职责 |
|---|---|
| `LegalDocument` | 三份文档的枚举；懒加载正文并计算 SHA-256（资源缺失时返回可读提示 + `sha256=missing`） |
| `LegalConsentStore` | `isAccepted()` / `accept()` / `current()`；写 `~/.starlight/legal/consent.json` + `consent-history.jsonl` |
| `LegalMarkdownView` | 把 Markdown 渲染成 JavaFX 节点（标题 / 段落 / 列表 / 引用 / 表格 / 粗体 / 行内代码 / 链接） |
| `LegalConsentGate` | 首启同意页：三份文档页签、主动勾选、同意/退出、窗口拖动 |

`consent.json` 结构（示例即字段全集）：

```json
{
  "schema": 1,
  "recordId": "（随机 UUID）",
  "acceptedAt": "2026-10-28T22:31:18.31+08:00",
  "launcherVersion": "1.0.0-RELEASE",
  "uiLanguage": "zh_CN",
  "os": "Windows 10 10.0 amd64",
  "mechanism": "explicit-checkbox",
  "documents": {
    "disclaimer": { "title": "免责声明", "sha256": "…", "bytes": 9259 },
    "eula":       { "title": "用户服务协议", "sha256": "…", "bytes": 21071 },
    "privacy":    { "title": "隐私政策", "sha256": "…", "bytes": 12199 }
  }
}
```

- **有效性判定**：记录中三份文档的 `sha256` 必须与当前 classpath 文本逐一致，否则 `isAccepted()` 返回 false。
  因此**改任何一份法律文本 → 旧同意自动失效 → 下次启动重新展示**，不依赖人工维护版本号。
- **台账**：每次同意向 `consent-history.jsonl` 追加一行（紧凑 JSON），不覆盖历史；主记录用临时文件 + 原子替换写入，
  避免写一半断电留下半截 JSON。
- **不写什么**：姓名、账号、邮箱、IP、主机名、设备指纹一律不写；`os` 只有名称/版本/架构，`recordId` 是随机 UUID。
  这一点与红线「不收集个人信息」一致，也写进了隐私政策 3.1 与安全与合规 8.1。
- **撤回**：删除 `~/.starlight/legal/` 即清除；下次启动重新确认。

### 3.4 界面

- **首启同意页**：图标 + 标题 + 版本号；三个页签（免责声明 / 用户服务协议 / 隐私政策）；正文滚动区；
  底部勾选框 +「不同意，退出」/「同意并继续」。**按钮默认禁用**，只有勾选后才可点击；关闭窗口（Alt+F4）
  视为不同意并退出；无边框窗口支持按住头部拖动。深浅主题与主界面同一套 `style.css` 变量。
- **设置 → 关于**：新增两张卡片 ——「法律文档」（三份全文，复用同一渲染器）与「同意记录」
  （时间 / 版本 / 打开记录目录）。
- **样式**：`style.css` 末尾新增 `.legal-*` 与 `.legal-consent-*` 两组；正文颜色统一取 `.root` 上的
  `-sl-text` / `-sl-text-dim`，不写死灰阶。表格用等宽分列的 `GridPane`，单元格是 `TextFlow`，
  因此表格里的反引号代码与粗体也能正确渲染（Label 会原样画出反引号）。
- **i18n**：`legal.*` 键在中英文包里各一份；三份文档的标题可随语言切换，`id` 永不翻译。
