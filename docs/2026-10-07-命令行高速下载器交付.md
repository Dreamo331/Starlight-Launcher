# 星光下载引擎 → 独立命令行高速下载器（starlight-dl）

交付日期：2026-10-07

落地目录：`G:\hello-starlight\starlight-launcher\temp\download\tool`

产物：`starlight-dl.jar`（可执行，零外部依赖，纯 JDK 17 标准库）



***

## 一、这是什么

把 Minecraft 启动器内置的「星光下载引擎」（`download.mod` 源管理 / 分块 / 停滞检测 / 限速）

剥离 MC 专用逻辑后，改造成的**通用命令行 HTTP (S) 多源高速下载器**。



* 直接可复用约 65% 引擎代码：多源候选 + 熔断 + 健康表、分块并发 + 动态再分裂、

  停滞看门狗 + 最后候选放宽、退避重试 + 慢源软硬双轨、全局限速 + 全局线程配额、校验状态缓存、非 ASCII URL 修复。

* 剥离掉的 MC 专用类：GameResourceCompleter / AssetDownloader / LibraryDownloader / InstallEngine /

  LoaderInstallEngine / VersionManifest / BMCLAPI/MCBBS/Mojang 镜像规则表 / ContentDownloader 等，全部不进入本工具。

* HostPolicy 黑名单反转：默认无任何单线程限制，仅当用户显式 `--single-host` 时对指定 host 单线程；坏源交给 SourceHealth 自动熔断。

## 二、本次补齐的四项关键能力（规格要求）



| 能力       | 实现位置                                                                                                               | 说明                                                                                                                                                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 跨会话断点续传  | `core/ResumeStore.java` + `core/DownloadFileTask.ensurePiecesFromResume()` + `core/DownloadPiece.setResumeState()` | 进度落盘 `<workDir>/.starlight-dl/<taskId>/meta.json`（url/mirrors/target/totalSize/etag/lastModified/pieces \[]），5s 节流写盘；启动比对 ETag/Last-Modified，远端变更则整体重下；**If-Range** 防远端变更后 Range 拼接坏文件（200/416 → FileChangedException → 清续传重下） |
| 任务队列与持久化 | `cli/Main.java` 分批调度 + `core/DownloadCoordinator`（保留）                                                              | `-j` 并发任务数上限（独立于分块线程数 `-t`）；按任务轮询终态；shutdown hook 落盘未完成任务续传元数据；目标路径去重防呆                                                                                                                                                        |
| 统一调度器    | `core/DownloadCoordinator`                                                                                         | 弃 GameResourceCompleter A/B 双池 + 等待池；失败重试下沉到单文件任务内部（`run()` 捕获失败 → 禁用失败源 → 换源整体重试一轮）                                                                                                                                           |
| 合并分块为一套  | `core/DownloadFileTask` + `core/DownloadPiece`                                                                     | ChunkedDownloader 逻辑并入单文件任务；首线程全量流与动态分裂子块的容量上限对齐（每轮重算 `cap = end-start+1-initialDone`），杜绝 Σdone 超 fileSize 导致的合并必败                                                                                                             |

另补：`GlobalSpeedLimiter.acquire` 改为 CAS 单次扣减 + 欠账 parkNanos（原实现循环重复扣令牌，低限速下欠账无限加深死锁）；`FileVerifier` 支持 SHA-256（64 位十六进制自动识别，原来只认 MD5/SHA-1，64 位被静默跳过导致 --sha256 校验失效）。

## 三、CLI 用法



```
java -jar starlight-dl.jar <URL...> [选项]

基础选项：
  -o <路径>          输出文件；多个 URL 时视为目录（自动取 URL 文件名）
  -t <N>             分块线程数（默认 8，1~64）
  -j <N>             并发任务数（默认 1，多 URL 时生效）
  -m <URL>           镜像候选，可重复指定；主源失败自动回退
  -s <KB/s>          全局限速（0=不限）
  --sha1 <hex>       校验 SHA-1（40 位）
  --sha256 <hex>     校验 SHA-256（64 位）
  --no-resume        禁用断点续传（默认启用）
  --work-dir <dir>   续传元数据目录（默认 <目标所在目录>）
  --single-host <h>  指定 host 单线程下载（可重复）
  --connect-timeout / --stall-timeout / --first-try-stall  超时调优
  --debug            输出调试日志
  -h / -V            帮助 / 版本

退出码：0=全部成功，1=存在失败，2=参数错误
```

示例：



```
# 单文件下载 + 镜像回退 + SHA-256 校验
java -jar starlight-dl.jar https://example.com/file.zip -o out.zip \
     -m https://mirror1.example.com/file.zip --sha256 <hex>

# 两个文件并发下载（-o 为目录），限速 5MB/s
java -jar starlight-dl.jar https://a/x.bin https://b/y.bin -o ./dl -j 2 -s 5120
```

## 四、实测证据（本机 127.0.0.1 测试服务器，12MB 确定性文件）



| 用例           | 场景                          | 结果                                                  |
| ------------ | --------------------------- | --------------------------------------------------- |
| T1 正常下载 + 校验 | 12MB / 8 分块                 | SUCCESS，SHA-256=`3bf8d043...904b9` 匹配，平均 19.35 MB/s |
| T2 断点续传      | 限速 512KB/s 跑 6s 强杀 → 重跑     | 「上次进度 22.5%」→ 续传完成，哈希匹配                             |
| T3 镜像回退      | 主源 127.0.0.1:1（死源，10s 连接超时） | WARN 换源重试 → 镜像 SUCCESS，37.27 MB/s，哈希匹配              |
| T4 错误哈希拦截    | --sha256 全零（错误值）            | exit 1 拦截，任务 FAILED（修复 SHA-256 识别前曾误报 SUCCESS）      |
| T5 多任务并发     | 2 个 12MB /-j 2 -t 6         | exit 0，aaa.bin/bbb.bin 哈希均匹配                        |

## 六、已知限制与后续路线



* HTTP (S) only；不做 BT / 磁力（协议栈与 HTTP 分块完全不共享）。

* 死源判定依赖连接超时（JDK HttpClient connectTimeout 已配 10s）；Windows 上被防火墙静默丢弃的连接仍按超时处理。

* 错误哈希拦截后的最终报错文案为「无可用下载源」（单源 + 哈希不符时无法换源），语义正确但文案不直观，可后续打磨。

* 校验状态缓存（VerifyStateCache）默认沿用，通用场景下建议后续提供开关（用户可能手改文件）。

* 后续可选：任务列表 UI（JavaFX）、速度曲线、If-None-Match、HTTP/3、暂停 / 恢复语义。

## 附录：GUI 前端（v1.0.0 新增）

Swing 实现，零外部依赖（不装 JavaFX 也能跑）。入口：

```
java -jar starlight-dl.jar --gui [URL...] [选项]    （简写 -g）
```

带 URL 时自动入队下载；不带则打开空窗口，点「新建任务」添加。

功能：

* 任务列表（表格）：状态 / 文件名 / 进度条 / 大小 / 速度 / 错误信息
* 实时全局速度曲线（120 点环形缓冲，显示当前值与峰值）
* 新建任务对话框：多 URL（每行一个）、镜像、输出 / 工作目录、分块线程数、并发任务数、限速 KB/s、SHA-1/SHA-256 校验、断点续传开关
* 工具栏：新建任务 / 取消所选（引擎级取消，续传元数据保留）/ 清理已完成 / 限速实时调整（不重启生效）
* 并发队列：`-j` 为「同时活跃任务数」，活跃不足时自动提交下一个排队任务
* 日志面板：引擎 System.out/err 实时转发
* 退出时自动保存全部未完成任务续传元数据（下次启动继续）

GUI 实测（本机测试服务器，12MB 确定性文件）：

| 用例 | 场景 | 结果 |
| --- | --- | --- |
| G1 自动入队下载 | GUI，单 URL / 12MB / -t 4 | 进程存活，file.bin 12582912 字节，SHA-256 匹配 |
| G2 多任务 + 限速 | GUI，2 个 12MB / -j 2 -s 5120 | aaa.bin / bbb.bin 哈希均匹配（限速 5MB/s 生效） |

源码新增：`temp\download\tool\src\com\starlight\dl\ui\GuiMain.java`；入口 `cli/Main.java` 增加 `--gui/-g` 分支。
测试目录：`temp\download\test-gui\`、`temp\download\test-gui2\`。

已知限制：GUI 的「暂停 / 恢复」暂为「取消 + 续传」语义（引擎无暂停 API）；后续可选 If-None-Match、HTTP/3、任务拖拽排序、系统托盘。
