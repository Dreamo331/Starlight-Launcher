# E0001 启动失败：签名一致性（Signer Information）修复记录

日期：2026-10-07
影响版本：1.16（class "dut"）、1.20.1（class "ezz"）——所有带 Mojang 签名的原版版本
错误码：E0001（未知错误）

## 一、现象

游戏启动立即失败，stderr 输出：

```
[authlib-injector] [INFO] Transformed [net.minecraft.client.main.Main] with [Main Arguments Transformer]
错误: 无法初始化主类 net.minecraft.client.main.Main
原因: java.lang.SecurityException: class "dut"'s signer information does not match signer information of other classes in the same package
```

- 1.16 报错类名 `dut`，1.20.1 报错类名 `ezz`，均为**无包名（根目录）混淆类**。
- 两个不同版本同样报错 → 问题不在单个游戏 jar，而在启动链路共性。

## 二、根因（已实证）

### 2.1 JVM 机制

Java 要求**同一包内**类的签名信息（CodeSigner）一致。系统类加载器（AppClassLoader）先加载了一个
**未签名**的无包名类，再加载**带 Mojang 签名**的无包名游戏类时，JVM 在
`ClassLoader.checkCerts → preDefineClass` 抛出 SecurityException。

### 2.2 事实核对

| 对象 | 包位置 | 签名状态 |
|---|---|---|
| `D:\新建文件夹 (15)\versions\1.16\1.16.jar` 混淆类（dut/eqb/…） | 无包名根目录 | Mojang 签名（META-INF/MOJANGCS.SF + MOJANGCS.RSA） |
| `lib/cape-url-patch-agent.jar` 的 `CapeUrlPatchAgent` / `CapeUrlPatchAgent$1` / `TestLoad` | **无包名根目录** | **未签名** |
| `authlib-injector.jar`（1.2.8） | `moe.yushi.authlibinjector.*` 命名包 | 未签名（无冲突） |

启动命令中 `-javaagent:...cape-url-patch-agent.jar=<端口>` 让 JVM 在游戏主类加载**之前**，先把
无包名未签名类 `CapeUrlPatchAgent` 定义进系统类加载器；随后游戏加载签名混淆类（如 `dut`）时
触发签名一致性检查失败。官方系启动器 + authlib-injector 无此问题，正是因为 authlib-injector
的类都在命名包内，不污染无包名包。

### 2.3 最小复现证据（temp/signer-repro）

- **Bad 场景**（未签名根包类 + 签名根包类）：`SecurityException: class "SignedRoot"'s signer
  information does not match ...`，堆栈 `checkCerts → preDefineClass`，与游戏日志一致。
- **Fixed 场景**（未签名命名包类 + 签名根包类）：PASS。

用真实 agent jar 实载模拟游戏场景（agent premain 先加载 → 再加载签名根包类）：
旧 jar 复现 SecurityException（exit=1）；新 jar PASS（exit=0）。

## 三、修复

**CapeUrlPatchAgent 源码移入命名包 `com.example.starlight.agent`，重新打包 agent jar。**
逻辑（常量池 Utf8 重写、端口参数、注册方式）保持不变，仅加包名声明与注释。

- 新源码：`tools/agent/CapeUrlPatchAgent.java`（长期文件，按项目约定放 /tools）
- 新 jar：`lib/cape-url-patch-agent.jar`
  - `Premain-Class: com.example.starlight.agent.CapeUrlPatchAgent`
  - `Can-Retransform-Classes: true`
  - 移除遗留测试类 `TestLoad.class`（无任何代码引用，已确认）
  - 编译目标：JDK 17（`--release 17`），避免"由更新版本编译"问题
- 启动器代码**无需修改**：LocalCapeProxy.agentJvmArg() 只引用 jar 绝对路径，
  UIGeneralControlClass / GameLauncherService / MenuHandler 三处注入逻辑不变。

## 四、验证

1. 新旧 agent jar 实载对比（真实 jar 模拟游戏场景）：旧 FAIL / 新 PASS。
2. 新 jar 常量池重写功能验证：加载含 `http://s.optifine.net/capes/114514.png`
   常量的类，输出 `已重写披风 URL 常量`，URL 变为 `http://127.0.0.1:7664/capes/114514.png`。
3. 后续请通过启动器实机启动确认（应不再报 E0001 / SecurityException）。

## 六、防御建议（后续）

- 本项目自研 javaagent 一律使用命名包，禁止无包名类（根目录类）。
- 游戏 jar 的 META-INF 签名文件不要删除/改写；本次无需动游戏 jar。
