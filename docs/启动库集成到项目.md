# 启动库集成进启动器项目（com.example.starlight.startmc）

日期：2026-10-01
背景：原 `com.startgame` 启动库以外部 jar（`lib/StarlightLauncher-2.0.0.jar`，需 `mvn install:install-file` 装入本地仓库）方式依赖，
存在"改了 lib 却忘记装 .m2 导致运行仍用旧代码"的风险（见 `docs/GLFW加载失败排查与修复.md` 第八节）。
本次将启动库源码直接集成进项目，消除外部 jar 依赖。

---

## 一、集成方式

启动库完整源码位于 `references\启动库jar源码（修复）\src\main\java\com\startgame`（共 8 个文件，与 jar 内类一一对应，含已修复的 getLibraries 逻辑）。
因源码完整，**直接适配源码而非反编译**（保留注释、保证可编译、行为与修复后 jar 一致）。

包名映射：

| 原包 | 新包 | 目标目录 |
|---|---|---|
| `com.startgame` | `com.example.starlight.startmc` | `src\main\java\com\example\starlight\startmc` |
| `com.startgame.launcher` | `com.example.starlight.startmc.launcher` | `src\main\java\com\example\starlight\startmc\launcher` |

类清单（8 个，含内部类）：

- `LaunchInfo`（含内部枚举 LoaderType）
- `launcher.BaseLauncher`（含内部类 CompatibilityHelper / NativeJarInfo；含 getLibraries 老格式 natives 修复）
- `launcher.VanillaLauncher` / `FabricLauncher` / `ForgeLegacyLauncher` / `ForgeModernLauncher`
- `launcher.LoaderDetector` / `PlatformUtils`（含内部枚举 OS）

## 二、同步改动

1. **项目引用更新**（10 个文件）：`com.startgame` → `com.example.starlight.startmc`
   - `gui/UIGeneralControlClass.java`（import 7 处）
   - `service/GameLauncherService.java`（含 `import ...startmc.launcher.*`）
   - `service/FileService.java`、`main/NativesManager.java`、`util/LegacyLaunchArgs.java`
   - `newui/GameCrashPanel.java`、`newui/LauncherView.java`、`newui/page/VersionSelectPage.java`、`newui/ui/VersionIconKit.java`
   - `version/VersionMatcher.java`
2. **pom.xml**：删除 `com.starlight:starlight-launcher-core:2.0.0` 依赖（及其 install-file 注释），替换为集成说明注释。
   `lib\StarlightLauncher-2.0.0.jar` 与 `.m2` 中旧坐标仅作备份保留，构建不再引用。

## 五、注意事项

1. 后续修改启动库逻辑直接改 `src\main\java\com\example\starlight\startmc\` 下源码即可，**不再需要** install-file 到本地仓库。
2. IntelliJ 需重新构建（或重启运行）以加载新包；若 IDE 缓存了旧依赖，Maven Reload 一次即可。
3. 若对外分发 GluonFX 单文件 EXE：源码已内置于项目，`build-single-exe.bat` 直接重新打包即包含集成后的代码。
