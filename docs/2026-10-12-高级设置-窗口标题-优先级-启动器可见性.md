# 高级设置新增：自定义游戏窗口标题 / 进程优先级 / 启动器可见性

> 2026-10-12 · 设置 → 高级设置 三张新卡片的设计与实现说明

## 功能一览

| 卡片 | 配置键（starlight.ini `[Launcher]`） | 作用对象 | 生效时机 |
|---|---|---|---|
| 自定义游戏窗口标题 | `GameWindowTitle` | 游戏进程的主窗口 | 下次启动游戏后 |
| 进程优先级 | `GameProcessPriority` | 游戏进程本身 | 下次启动游戏后 |
| 启动器可见性 | `LauncherVisibility` | 启动器窗口 | 游戏窗口就绪 / 游戏退出两个时机 |

三项都支持「版本独立设置」体系的合并读取（走 `LaunchConfig.fromIni`，全局值统一生效；如需按版本覆盖可在 `VersionConfigManager` 注册路径，本次未加）。

## 一、自定义游戏窗口标题

### 为什么不能走启动参数

Minecraft 没有任何「自定义窗口标题」的启动参数或系统属性：标题由游戏自己在 `Window.setTitle()` 里写死成 `Minecraft* <版本>`。唯一可行的系统级做法是：**找到游戏进程的主窗口，直接改窗口文字**。

### 实现（`util/GameProcessTweaks`）

```
BaseLauncher.startProcessWithMonitoring()
        │  pb.start() 后调用
        ▼
GameProcessTweaks.applyOnProcessStarted(pid, title, priority)
        │
        ├─ 优先级：立即设置（见下节）
        └─ 标题：启动监视线程（game-window-title，守护线程）
                30 秒内每 500ms 枚举一次窗口
```

- **主窗口判定**：窗口可见、有标题，且满足其一——
  窗口类名以 `glfw` 开头（MC 1.13+ 的 GLFW 窗口）｜标题含 `Minecraft`｜标题已等于自定义值（**重写时必须靠这条再次命中**，否则第二次轮询就找不到窗口了）
- **反复重写**：游戏自己也会设标题（窗口创建时一次，部分版本加载世界/断线后再设），只改一次会被覆盖；写同值无副作用
- **日志**：只记一次「游戏窗口标题已设置为：…」，避免 60 轮轮询灌满启动日志
- **规范化**（`normalizeTitle`）：去首尾空白、换行（`\r\n`/`\r`/`\n`）折成单个空格、限长 200

### 变量支持（`expandTitle`）

输入框里填的是**模板**，原样保存到 ini，只在启动时展开：

| 变量 | 展开为 | 示例 |
|---|---|---|
| `{version}` | 本次启动的游戏版本名 | `Minecraft-{version}` → `Minecraft-1.20.1` |
| `{username}` | 当前玩家名 | `{username} 的世界` → `Steve 的世界` |

- 展开发生在 `BaseLauncher.startProcessWithMonitoring()` 里：`expandTitle(launchInfo.getWindowTitle(), launchInfo.getVersion(), launchInfo.getUserName())`，两条启动路径（新版 UI / 插件 API）都覆盖
- **未知变量原样保留**（用户手打错的能看出来）；**已知变量值缺失时展开为空串**（版本名读不到时标题停在 `Minecraft-{version}` 会让人误以为变量不生效）
- 展开后再次限长 200，保证最终生效值不超限
- 设置页带**实时预览**：输入时按当前版本/玩家名展开显示「实际效果：…」，无需保存再启动游戏验证写法

### 双通道（与 `MemoryOptimizer` 同款约定）

| 环境 | 通道 | 说明 |
|---|---|---|
| JVM 模式 | JNA：`EnumWindows` + `SetWindowText` | user32 里没有平台层封装的 `SetWindowText` 单独声明了一个 `User32Ext`（挂 `W32APIOptions.UNICODE_OPTIONS`） |
| GraalVM native | PowerShell `Add-Type` P/Invoke | **JNA/OSHI 静态初始化失败会打死调用线程**，native 分支绝不触碰 JNA 类（见 `NativeImageCompat`） |

非 Windows 平台静默跳过（无稳定的无依赖 API）。

### ⚠️ 修改标题的连带影响

按窗口标题匹配游戏窗口的功能要跟着改：**色盲辅助**（`ColorBlindOverlayManager`，默认抓 `Minecraft`）在标题里没有 "Minecraft" 后会抓不到窗口。设置页描述里已注明；「色盲辅助 → 游戏窗口标题」填自定义标题即可。

## 二、进程优先级

### 选项（`PRIORITY_OPTIONS`）

| 值 | 文案 | Windows 常量 |
|---|---|---|
| `low` | 低 | `IDLE_PRIORITY_CLASS` |
| `below_normal` | 低于正常 | `BELOW_NORMAL_PRIORITY_CLASS` |
| `normal` | 正常（默认） | 不设置 |
| `above_normal` | 高于正常 | `ABOVE_NORMAL_PRIORITY_CLASS` |
| `high` | 高 | `HIGH_PRIORITY_CLASS` |
| `realtime` | 实时 | `REALTIME_PRIORITY_CLASS`（UI 里注明不建议） |

### 实现

- **Windows / JVM**：JNA `OpenProcess(PROCESS_SET_INFORMATION)` → `SetPriorityClass`，失败降级 `PROCESS_QUERY_LIMITED_INFORMATION` 再试
- **Windows / native**：PowerShell 兜底，C# 侧一次完成「优先级 + 标题」并打印 `PRI=True/False`、`TITLE=True/False/SKIP`；Java 侧**解析输出标记判成败，不看 powershell 退出码**（`$ErrorActionPreference=SilentlyContinue` 下编译失败也退 0，看退出码会把「什么都没做」报成成功）
- **Linux / macOS**：`renice -n <nice> -p <pid>`（负值需权限，失败静默）
- `normalizePriority`：大小写不敏感，未知值回落 `normal`；`normal` 时直接返回成功、零开销

## 三、启动器可见性

### 五种策略（`newui/LauncherVisibility`）

| 值 | 界面文案 | 游戏窗口就绪时 | 游戏退出时 |
|---|---|---|---|
| `keep`（默认） | 游戏启动后仍保持不变 | 无动作 | 无动作 |
| `close` | 游戏启动后立即关闭 | 退出启动器 | —（已退出） |
| `hide_close` | 游戏启动后隐藏，游戏退出后自动关闭 | `stage.hide()` | 退出启动器 |
| `hide_restore` | 游戏启动后隐藏，游戏退出后重新打开 | `stage.hide()` | `show()` + 置前抢焦点 |
| `minimize` | 游戏启动后最小化 | `setIconified(true)` | 还原 + 置前 |

### 接入点（`LauncherView.launchGame`）

```
launchGame()
  ├─ visibilityMode = 启动时读一次策略          ← 启动/退出两个时机用同一个值，
  │                                                避免中途改配置导致「隐藏了却不还原」
  ├─ 进度回调：isExitRequested() 为真则直接返回   ← 关闭策略下 JavaFX 正在关，
  │                                                再 runLater 会抛 IllegalStateException
  ├─ onGameStarted（游戏窗口就绪，runLater 内）：
  │     先让启动动画走完自己的收尾（markSuccess + 1.5s 退出定时器）
  │     再 LauncherVisibility.onGameStarted(stage, mode)
  │     真的隐藏/最小化/关闭了 → launcherHiddenByVisibility.set(true)
  ├─ onSuccess / onError（游戏退出或启动失败）：
  │     applyLauncherVisibilityOnExit(mode)
  │       只在确实动过窗口时执行（getAndSet(false) 原子取旧值），
  │       「隐藏后自动关闭」在这里退出；启动失败时还原窗口但绝不额外退出
  └─ onError 同样有 isExitRequested 短路
```

### 「关闭」为什么必须结束进程

只调 `Platform.exit()` 的话，JVM 会因为**游戏 stdout/stderr 读取线程不是守护线程**而一直挂到游戏结束——用户看到的就是「启动器窗口关了但进程还在」。所以统一退出路径是：

```
exitLauncher()
  ├─ exitRequested 标记（volatile，幂等）
  └─ Platform.runLater { Platform.exit(); System.exit(0) }
```

shutdownHook 会照常收掉插件子进程、色盲矫正工具等；游戏是独立子进程不受影响。

## 四、数据流（配置 → 生效）

```
starlight.ini [Launcher]
  GameWindowTitle / GameProcessPriority / LauncherVisibility
        │  三个键都已登记白名单（漏登记 = 保存后重启即丢）：
        │    ConfigManager.saveConfig()          主写入口
        │    UIGeneralControlClass.saveConfig()   旧 UI 写入口
        │    StarlightConfig.LAUNCHER_KEYS        键清单
        ▼
LaunchConfig.fromIni()   ← 两处：model.LaunchConfig 与 UIGeneralControlClass.LaunchConfig
        ▼
buildLaunchInfo()        ← GameLauncherService 与 UIGeneralControlClass 各一份，
        │                   都补了 setWindowTitle / setProcessPriority
        ▼
LaunchInfo               ← startmc.LaunchInfo 新增 windowTitle / processPriority 字段
        ▼
BaseLauncher.startProcessWithMonitoring()   进程级微调的唯一落地点
        ▼
GameProcessTweaks.applyOnProcessStarted()
```

「启动器可见性」不进启动链路：它是启动器窗口行为，由 `LauncherView` 直接读 `configCache` 应用。

启动参数日志（PCL 标准「启动参数开始/结束」区块）在设置了非默认值时会追加两行：`窗口标题：…`、`进程优先级：…`。

## 六、验证记录

| 验证项 | 方法 | 结果 |
|---|---|---|
| 编译 | `mvn -o compile` | BUILD SUCCESS |
| JNA 路径 | 拉起真实 Swing 窗口（标题 `Minecraft 1.20.1`），调用 `setPriority` + `applyWindowTitle`，用 `Get-Process` 读回 | `MainWindowTitle=[StarLight Custom Title]`、`PriorityClass=[High]` ✓ |
| PowerShell 兜底 | 反射强制走 `windowsApiViaPowerShell`，同样读回 | 标题与优先级均真实生效 ✓ |
| 配置链路 | `ChainSmoke` 23 项断言（ini 透传、归一化、枚举顺序、空值 no-op） | ALL PASSED ✓ |
| 变量展开 | `VarSmoke` 11 项断言（版本/玩家名/双变量/未知变量保留/缺失清空/换行折叠/展开后限长） | ALL PASSED ✓ |
| 变量端到端 | 模板 `Minecraft-{version} [{username}]` 展开后写入真实窗口，读回 | `MainWindowTitle=[Minecraft-1.20.1 [Steve]]` 与期望一致 ✓ |

### 验证过程中发现并修复的坑（PowerShell 兜底路径）

1. **`-Command` 引号吞噬**：脚本里全是双引号，`powershell -Command <script>` 的命令行解析先吃掉一层，`Add-Type` 拿到的 C# 变成 `[DllImport(kernel32.dll, ...)]` 直接编译失败；而 `$ErrorActionPreference=SilentlyContinue` 把错误吞掉 → powershell 退 0、实际什么都没做的**假成功**。
   → 改用 **`-EncodedCommand`**（Base64 + UTF-16LE），单个 token 不经任何引号处理（PowerShell 3.0+，Win8 起内置）。
2. **C# 三元表达式类型不一致**：`cond ? tit : "SKIP"`（bool vs string）编译失败，同样被吞。→ 改 `tit.ToString()`。
3. **PowerShell 脚本块→委托**：原来把 `EnumWindows` 回调写成 PS 脚本块，依赖作用域捕获、极易静默失效。→ 全部逻辑（含回调）下沉到 C#，PS 侧只调 `StarTweaks::Run(pid, cls, want)`。

## 七、已知限制

- 窗口标题仅 Windows 生效；`realtime` 优先级可能拖累系统响应（UI 已提示）
- 改标题后按标题匹配的伴生工具（色盲辅助）需同步修改其「游戏窗口标题」配置；模板里保留 `{version}` 时标题仍以 `Minecraft` 开头，默认匹配不受影响
- 变量在**启动时一次性展开**：游戏运行期间版本名/玩家名不会变，无需动态刷新
- 「启动器可见性」的关闭/隐藏只在**新版 UI**（`LauncherView`）生效；CLI 启动模式无窗口，不涉及
- 优先级在进程存活期间有效，游戏退出自动失效
