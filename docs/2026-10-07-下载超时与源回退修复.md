# 下载安装超时修复：镜像优先 + 官方兜底候选链

日期：2026-10-07
关联问题：安装版本时大量 `[VersionDownloadService] Request failed: ... -> request timed out / HTTP connect timed out`
参照实现：references/download（PCL2 ModDownload.vb，`DlSourceOrder`：镜像优先、官方兜底、去重、逐 URL 超时）

## 一、现象

安装/查询版本时控制台刷屏：

```
[VersionDownloadService] Request failed: https://bmclapi2.bangbang93.com/mc/game/version_manifest.json -> request timed out
[VersionDownloadService] Request failed: https://meta.fabricmc.net/v2/versions/loader/26.2 -> request timed out
[VersionDownloadService] Request failed: https://bmclapi2.bangbang93.com/maven/net/neoforged/neoforge/maven-metadata.xml -> HTTP connect timed out
[VersionDownloadService] Failed to fetch version manifest from download source.
```

实测（2026-10-07）：所有源均可达（fabric-meta 镜像 59ms、maven.neoforged.net 1.2s、官方 manifest 0.6s），
但 BMCLAPI 高峰期会**瞬时 connect 超时**。旧代码一碰到镜像抖动就整条查询失败，且无回退。

## 二、根因（4 处）

1. **元数据请求绕过下载源镜像**：Fabric/NeoForge 等 LoaderProvider 硬编码官方域名
   （`meta.fabricmc.net`、`maven.neoforged.net`），直接调 `fetchString`，BMCLAPI 的
   fabric-meta / maven 镜像替换规则从未生效。国内访问官方 fabric meta 本就不可靠。
2. **`injectURLWithCandidates` 只有镜像没有兜底**：镜像规则命中时只返回镜像一条，
   BMCLAPI 抖动 → 文件下载（库/资源/客户端 jar）也只试镜像，失败即失败。PCL 做法是
   `MirrorUrls.Union(OfficialUrls)`（镜像优先 + 官方兜底）。
3. **版本清单回退 Bug**：`doFetchVersionManifest` / `VersionManifest.fetchVersionList`
   在「选中源恰为 BMCLAPI」时不回退官方——正好命中用户场景（默认源 BMCLAPI + BMCLAPI 抖动
   → 直接 "Failed to fetch version manifest"）。
4. **超时一刀切**：所有请求统一 15s，镜像与官方没有区分；失败后 H2/H1.1 双倍耗时，
   无候选链时浪费在死源上。

## 三、修复（对标 PCL DlSourceOrder）

| 文件 | 改动 |
|---|---|
| `download/source/BMCLAPIDownloadProvider.java` | `injectURLWithCandidates` 命中镜像时返回 `[镜像, 官方]`（去重兜底） |
| `download/source/MCBBSDownloadProvider.java` | 同上 |
| `version/VersionDownloadService.java` | ①`fetchString` 改为候选链：选中源镜像 → BMCLAPI 镜像（自动兜底）→ 官方原始 URL，逐候选先 H2 后 H1.1，**镜像 6s / 官方 20s**；②`doFetchVersionManifest` 候选链：选中源 → BMCLAPI → MCBBS → piston-meta → launchermeta，去掉 `instanceof` 回退 Bug；③清单在途上限 60s→90s |
| `version/NeoForgeProvider.java` | 去掉手写「先 BMCLAPI 再官方」两段请求，统一走 `fetchString` 官方 URL 由候选链自动加镜像 |
| `download/task/VersionManifest.java` | 清单候选链同上，修复 `instanceof` 回退 Bug |
| `download/task/LoaderInstallEngine.java` | `fetchString` 同样镜像优先 + 官方兜底 |

启动器无需重新打包 jar；改动均在前端源码，重编译即可生效。

## 四、验证

1. **增量编译**：6 个文件 `javac --release 17` 编译通过（输出到 `temp/fix-classes`，未动 target）。
2. **实机候选形状检查**（纯本地，无网络）：BMCLAPI 源下
   `meta.fabricmc.net/...` → `[bmclapi fabric-meta, 官方]`；`maven.neoforged.net/...` → `[bmclapi maven, 官方]`；
   MCBBS 源同理；Mojang 源保持官方（运行时自动追加 BMCLAPI 兜底）。与 PCL `DlSourceOrder` 一致。
3. **实机联网（验证期间 BMCLAPI 恰好抖动，等于压力测试）**：
   - FabricProvider 最新加载器（26.2）→ **619ms 成功**（经 bmclapi fabric-meta 镜像），`available=true`
   - 版本清单：bmclapi connect 超时 → MCBBS DNS 失败 → **官方 piston-meta 成功，count=918**。
     修复前此场景（选中源=BMCLAPI）直接返回空。
   - NeoForge 元数据：验证时段 bmclapi 与 maven.neoforged.net 同时故障（connect 超时 / TLS 握手失败），
     正确返回不可用；其单独探测（1.2s）正常，属宿主瞬时抖动。

## 六、后续建议

- BMCLAPI 抖动是常态，若安装仍偶发失败属宿主瞬时故障，候选链会自动换源重试，重试一次即可。
- 下载源设置建议保留默认 BMCLAPI（国内最快）；官方源已作为自动兜底存在于每条请求链中。
