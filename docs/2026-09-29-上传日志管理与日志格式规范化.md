# 日志上传管理（结果窗口 + 记录中心）与日志格式规范化

> 日期：2026-09-29 ｜ 范围：本仓库当前工作区
> 关联：docs/2026-09-29-日志上传切换LogshareAPI.md（Logshare API 接入）

## 一、上传成功后的结果窗口

上传日志成功后（崩溃面板「上传日志」），弹出独立的结果窗口，包含：

- **二维码**：展示分享地址生成的二维码；
  - PNG 保存到系统临时目录 `%TEMP%\starlight-qr\starlight-log-<id>.png`（C 盘临时目录），
    **不再自动打开资源管理器**（原先 `LogExporter.openInExplorer` 的行为已移除）；
  - 二维码生成失败时降级为提示文案，链接仍可复制使用。
- **地址框**：只读展示分享链接 + 「复制」按钮（复制到系统剪贴板并 Toast 提示）。
- **撤回按钮**：用创建时返回的 token 调 `DELETE /v1/log/{id}` 撤回日志，成功后：
  - 删除本地记录（`uploaded_logs.json`）、关闭窗口、刷新资源页列表；
  - 旧版端点 / 自定义服务器无 token 时按钮禁用并提示原因；
  - 删除接口幂等：日志已被删除 / 不存在（HTTP 400 + 内部 404「Log not found」）视为成功。

## 二、上传记录持久化与「资源页 → 上传的日志」

- **持久化**：`Starlight-Launcher/uploaded_logs.json`（与 starlight.ini 同级），每次上传成功立即写入
  `id / url / 删除 token / 文件名 / 上传时间 / 文件数`；token 只在创建响应返回一次，丢失无法找回，
  因此持久化是撤回能力的唯一保障。文件损坏时自动备份为 `.corrupt-<时间戳>` 后重建，不影响启动器。
- **资源页新增「上传的日志」栏目**（侧边栏，位于「崩溃报告」之后）：
  - 列表显示：名称、上传时间、文件数、分享链接（支持搜索）；
  - 操作：**复制链接** / **再次分享**（重新打开结果窗口：二维码 + 地址 + 撤回）/ **撤回删除**
    （调 DELETE 撤回日志并删除本地记录，带二次确认）。

## 三、日志输出格式对齐 HMCL 规范

参考 `temp/log.txt`（HMCL 日志规范），统一为 **`[时间] [线程/级别]: 消息`**：

- `logback.xml`：FILE 与新增 CONSOLE appender 均使用 `[%d{HH:mm:ss}] [%thread/%level]: %msg%n`；
  控制台级别着色（INFO 白 / WARN 黄 / ERROR 红），文件落盘为纯文本；轮转策略不变。
- `util/DebugLog.java`：时间戳去掉毫秒，报文行由 `[网络 发送] POST ...` 改为
  `[网络/INFO]: 发送 POST <url> <状态> | 数据包 <大小> | 耗时 <ms>`（英文模式 `[NET/INFO]: SEND ...`）。

## 四、sendlogs 接口变更

- 新增 `UploadResult{id, url, token}`：上传返回完整记录而非仅链接；
- 新增 `uploadLogFileEx` / `uploadLogBundleEx`（返回 `UploadResult`），原返回 String 的方法保留并委托；
- 新增 `deleteLog(id, token)`：DELETE `/v1/log/{id}`（Bearer token），幂等处理「日志不存在」；
- 响应解析支持 v1（id/token/url）与旧版端点（url/shortUrl/id，token 为 null）。
