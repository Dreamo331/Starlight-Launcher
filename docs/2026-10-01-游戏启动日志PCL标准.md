# 游戏启动日志改为 PCL 标准

日期：2026-10-01
参考：`references/PCL-main`（Plain Craft Launcher 2 完整 VB.NET 源码）
需求（用户确认）：**启动游戏流程日志** 与 **启动器自身运行日志** 两者都改为 PCL 标准；启动流程日志**仅写日志文件**（类似 PCL 的 `Log1.txt`），界面启动动画维持现状。

## PCL 标准（取自 PCL 源码）

- **界面启动日志**（`Modules\Minecraft\ModLaunch.vb` 的 `McLaunchLog`）：
  `[HH:mm:ss.fff] 文本`，无级别前缀，累积显示在启动页右侧日志区。
- **文件日志**（`PCL\Log1.txt`，PclLogger）：带级别前缀的持久化日志，崩溃分析时收集。
- **启动流程关键文案**（ModLaunch.vb 91 处 `McLaunchLog` 调用）：
  `预检测已通过` → `登录方式：离线（xxx）/正版（xxx）` → `选择的 Java：xxx` →
  `参数获取开始` + `=================== 启动参数开始 ===================`（每行一个参数）+
  `=================== 启动参数结束 ===================` → `正在解压 Natives 文件` →
  `已更新 launcher_profiles.json` → `已启动游戏进程：<java.exe>` →
  空行 + `~ 基础参数 ~`（版本/内存/MC 文件夹/Java 信息…）+ `~ 登录参数 ~`
  （玩家用户名/AccessToken/UUID/登录方式）→ `开始启动结束处理` → `错误：xxx` / `已取消启动`。

## 改动文件

### 1. 新增 `src/main/java/com/example/starlight/util/LaunchLog.java`

启动流程日志工具（PCL 标准）：
- `info / warn / error(String)`：行格式由 logback 统一输出为 `[HH:mm:ss.SSS] [级别] 文本`；
  写入 `logs/starlight.log`（与启动器运行日志同一文件，类似 PCL 的 Log1.txt），不触碰 UI。
- `mask(String)`：AccessToken / UUID 等敏感字段打码（保留前 4 + 后 4，中间 `****`），
  与 PCL `PclLogger.FilterAccessToken` 行为一致。

### 2. `src/main/resources/logback.xml`

- 控制台与文件 pattern 从 HMCL 风格 `[HH:mm:ss] [线程/级别]: 消息` 改为 **PCL 风格**
  `[HH:mm:ss.SSS] [级别] 消息`（毫秒级时间 + 级别前缀）。
- 控制台 `%highlight()` 着色保留；**新增 `<charset>UTF-8</charset>`**：
  修复 Windows 平台默认 GBK 写盘导致的跨工具中文乱码（此前日志文件是 GBK）。

### 3. `src/main/java/com/example/starlight/gui/UIGeneralControlClass.java`（主入口，新/旧 UI 共用）

`launchMinecraftAsync` 启动流程插入 PCL 标准日志（`LaunchLog`）：
- `预检测已通过`、`登录方式：离线（xxx）/正版（xxx）`（按 userType 判定）
- AutoJava：`选择的 Java：<path>` / `未找到合适的 Java，使用当前配置`
- `正在读取版本信息...`、`检测到加载器：xxx`、`正在准备游戏资源...`、`正在初始化路径...`
- `正在解压 Natives 文件`（PCL 文案）、`正在应用版本设置（语言 / 全屏）...`
- **启动参数区块**：`参数获取开始` + `==== 启动参数开始 ====`（mainClass / Java / 最小内存 /
  最大内存 / 游戏版本 / 游戏目录 / 版本隔离 / 窗口大小 / JVM 参数 / 游戏参数）+
  `==== 启动参数结束 ====`
- `已启动游戏进程：<java>（PID xxx）`（进程回调内）
- 退出后：空行 + `~ 基础参数 ~`（游戏版本 / 分配的内存 / MC 文件夹 / 版本隔离 / Java 信息）+
  `~ 登录参数 ~`（玩家用户名 / AccessToken[mask] / UUID[mask] / 登录方式）+
  `开始启动结束处理` + `游戏已退出，运行时长：N秒`
- `stopLaunchingInstance`：`已取消启动`；catch 块：`错误：<msg>`

### 4. `src/main/java/com/example/starlight/service/GameLauncherService.java`（插件 API 入口）

与上述同构的插入点（预检测/登录方式/版本信息/加载器/资源/路径/Natives/版本设置/
参数区块/已启动游戏进程/基础参数/登录参数/开始启动结束处理/错误/取消），
`stopGame` 加 `已取消启动`。

- 运行时冒烟（`temp/smoke-pcl-launchlog/`，真实 logback 加载）：

  - 全流程文案逐行落盘 ✓；`[WARN ]` / `[ERROR]` 级别正确 ✓
  - 敏感字段打码：`AccessToken：eyJh****sw5c`、`UUID：1234****9012` ✓
  - **UTF-8 落盘**：日志文件中文正常（修复前为 GBK 乱码）✓

## 备注

- `logs/starlight.log` 即启动器运行日志文件（exe 运行目录下 `logs/`），启动流程日志与
  启动器日志合并落盘，对应 PCL 的 `Log1.txt` 语义；轮转策略（10MB/7 天/500MB 上限）不变。
- 旧的 HMCL 风格（`[时间] [线程/级别]: 消息`）被 PCL 风格替换；`DebugLog` 网络日志的消息内
  `[网络/INFO]:` 语义前缀保留，行时间格式随 logback 统一为 PCL 风格。
