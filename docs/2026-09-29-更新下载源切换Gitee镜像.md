# 2026-09-29 更新下载源切换 Gitee 镜像

## 背景

用户反馈「更新软件连接下载服务器的时间特别长」。原因是：官方更新接口（`auth.php?action=launcher_update`）返回的 `download_url` 直链，下载对国内用户较慢。

版本安装包本来就同时发布在 Gitee 与 GitHub 仓库（发行版带 `.exe` 附件），Gitee 国内直连最快。

## 方案

版本检查与下载解耦：

| 环节 | 来源 | 说明 |
|---|---|---|
| 版本检查 | 官方服务器 | 维持现状，官方是唯一能给出 `md5` / `force_update` 的来源 |
| 下载源（1） | **Gitee** | 官方给出版本信息后优先替换为 Gitee 发行版 `.exe` 直链，国内直连最快 |
| 下载源（2） | GitHub | Gitee 拿不到直链时备用 |
| 下载源（3） | 官方直链 | 两个镜像都不可用时兜底（与旧行为一致） |

替换条件（两个都满足才替换，避免下到错的包）：

1. 镜像仓库最新版本与官方 `version` **完全一致**（`compareVersions == 0`，兼容 `1.0.1` 与 `1.0.1-RELEASE` 这类同号转正）；
2. 该发行版附了 `.exe` 安装包直链。

`md5` / `force_update` / 更新说明始终以官方为准，镜像只贡献下载地址。

## 改动文件

- `src/main/java/com/example/starlight/util/UpdateChecker.java`
  - `UpdateResult` 新增 `downloadSourceLabel` 字段（实际下载源：Gitee / GitHub / 空=官方直链）；
  - `Candidate` 新增 `downloadSource` 字段；
  - 官方路径 `checkBlocking` 改为先取官方版本信息，再调用新增的 `attachPreferredMirror` 替换直链；
  - 新增 `attachPreferredMirror`（Gitee 优先 → GitHub 备用 → 官方兜底）与 `isSameVersion`（版本一致性校验）；
- `src/main/java/com/example/starlight/newui/update/UpdateCoordinator.java`
  - `sourceHint` 展示下载源信息：「版本信息来自官方服务器，安装包下载源：Gitee / GitHub」；
  - 更新对话框中「下载地址」直接显示替换后的镜像链接，保持透明可排查。

## 行为说明

- 官方检查失败时仍走原有 GitHub / Gitee 并发竞速降级逻辑，不受本次改动影响；
- 镜像替换失败（网络失败 / 仓库未同步 / 未附 `.exe`）静默回退官方直链，用户无感知；
- 下载前仍按官方 `md5` 校验完整性，镜像替换不会绕过校验；
- 调试模式下 `DebugLog` 记录「更新下载源切换为 Gitee/GitHub」，可在开发者选项页查看。

## 验证

- `mvn -DskipTests compile` 编译通过；
- 逻辑验证点：
  1. 官方 `version` 与 Gitee 最新 release 版本一致 → 用 Gitee 直链；
  2. Gitee 版本未同步 / 无 `.exe` 附件 → 试 GitHub；
  3. 两者都失败 → 保留官方 `download_url` 兜底；
  4. 官方服务器不可用 → 原有 GitHub/Gitee 竞速降级，行为不变。
- 待上线后实测：Gitee 仓库最新 release 需与官方 `version` 同步发布（含 `.exe` 附件），否则会走兜底直链。
