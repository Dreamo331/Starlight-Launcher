# 2026-10-12 网络请求空返回不被记录修复

## 问题

开发者工具（网络请求统计悬浮窗 + 调试日志）里，**assets / libraries 下载产生的「200 空返回」既不进调试日志，也不进「空返回」计数**。
BMCLAPI 典型故障形态就是返回 `HTTP 200` 但正文 0 字节，而这条记录在开发者工具里完全看不到。

## 根因

请求级埋点统一走 `DebugLog.http(direction, method, url, status, bytes, content, costMs)`，
它内部先调 `NetTrafficStats.onHttp(...)` 做全程统计（发送/成功/失败/空返回），再写调试日志。

排查发现 `NetTrafficStats.recordBytes(...)`（字节流量）与 `DebugLog.http(...)`（请求计数）是**两套埋点**：

- `GameResourceCompleter`（主资源补全）：两套都埋了 → 空返回能记。
- `AssetDownloader`（assets）、`LibraryDownloader`（libraries）：**只埋了 `recordBytes`，完全没有 `DebugLog.http`**。

于是这两条 BMCLAPI 空返回高发路径：
- SEND 没记 → 「发送」计数漏；
- 读完没记 RECV → `totalRead==0` 的空返回不会走到 `onHttp(false,200,0)` → 「空返回」计数不涨；
- 调试日志里也没有 `[NET RECV] ... | pkt 0 B` 这一行。

## 修复

在两个下载方法 `downloadFile(...)` 对齐 `GameResourceCompleter` 的埋点模式：

1. `getResponseCode()` 之前发 SEND；
2. 非 2xx 分支发 RECV(status=code, bytes=0)；
3. 读完正文后发 RECV(status=code, bytes=totalRead) —— **空返回时 totalRead=0，由 `onHttp` 判为 EMPTY**；
4. `catch IOException` 发 RECV(status=0, bytes=0, "请求失败: "+msg)，保证 SEND/RECV 配对。

空返回判定业务逻辑（`SourceHealth.recordEmpty`、0 字节删文件换源）保持原样不动，
本次只补齐「记录」这一环。

## 验证

- `javac -encoding UTF-8 -cp target\classes;lib\*;gson` 编译两文件通过（EXIT=0）。
- 运行时空返回路径：`DebugLog.http(false, url, 200, 0, "[二进制文件]", -1)` → `onHttp(false,200,0)` → `2xx && bytes<=0` → `EMPTY++`，并在调试日志输出 `[NET RECV] url 200 | pkt 0 B`。
