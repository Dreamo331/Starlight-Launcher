# Starlight Launcher 离线皮肤转接文档

> 面向接手者 / 复现者的**接线指南**：离线账号（如 `114514`）的自选皮肤与披风如何从启动器一路到达游戏画面。
> 配套记录（逐轮修复经过）：`docs/2026-10-01-离线皮肤改造PCL2风格.md`。本文只讲**现状怎么接、改哪里、怎么验证**。
> 适用版本：1.17.1-OptiFine_H1（纯 OptiFine，启动走 Forge(Legacy) LaunchWrapper + OptiFineTweaker 分支），游戏目录 `D:\新建文件夹 (15)`，版本隔离开启。

---

## 1. 整体机制：两层通道

离线玩家（1.17+）的皮肤与披风是**两条互不相干的通道**，由反编译实证得出，缺一不可：

| 通道 | 机制 | 对应代码 |
| --- | --- | --- |
| **皮肤** | PCL2 风格：UUID 微调定模型（Steve/Alex）+ `Starlight Skin.zip` 资源包覆盖内置默认贴图 | `OfflineSkinUuid` + `OfflineSkinPack` |
| **披风** | 本地 Yggdrasil 档案服务器 + `--profileProperties` 注入（原版通道，对本地玩家实际不触发网络）+ **本地 HTTP 代理劫持 OptiFine 的 `s.optifine.net/capes/<名>.png` 下载**（唯一真实生效通道） | `LocalYggdrasilServer` + `LocalCapeProxy` |

> 关键事实（反编译实证，`%TEMP%\dvp_of.txt / eyc_of.txt / eyc1.txt / gt.txt / capet.txt / acp.txt`）：
> - 1.17+ 本地玩家 `SkinManager` 直接取 Session profile 的 textures 属性，**不查会话档案**；注入 `--profileProperties` 后游戏不再有任何档案/贴图网络请求（所以披风必须走 OptiFine 通道）。
> - OptiFine 修改的 `AbstractClientPlayer` **构造直接调用 `CapeUtils.downloadCape(this)`**（本地玩家实体创建必触发），URL 固定 `http://s.optifine.net/capes/<玩家名>.png`，下载成功才 `setLocationOfCape` 并渲染；失败/404 静默。**没有任何本地回退或资源包披风通道**。
> - 皮肤则相反：`AbstractClientPlayer` 构造从 `MinecraftClient.getSkinTextureLocation()` 拿贴图，该位置由资源包覆盖 → **皮肤走资源包**。

## 2. 皮肤通道转接

### 2.1 UUID 微调（`auth/offline/OfflineSkinUuid.java`）

- **原理**：离线玩家默认皮肤模型由 UUID 决定。保持玩家名不变，把传给游戏的 `auth_uuid` 微调到「游戏判定为目标模型」。
- **模型判定**（PCL2 `McSkinSex`）：无连字符 32 位 UUID 第 7/15/23/31 位半字节 XOR，**奇数=Alex、偶数=Steve**。
- **算法**：以账号基础 UUID 为起点，`skinSex()` 命中目标即停；否则末 5 位 +1（末位半字节奇偶必翻转，最多 1 次命中），上限 100_000 次防死循环。
- **类型映射**：DEFAULT=不动；STEVE/ALEX=直接求；内置皮肤（ARI/EFE/...）跟随官方模型；LOCAL_FILE/LITTLE_SKIN/CSL API=跟随用户选择的 slim/wide。

**调用点（三路径，均以账号基础 UUID 为起点、幂等）**：
- `gui/UIGeneralControlClass.launchMinecraftAsync`（~608 行）
- `service/GameLauncherService.launchMinecraftAsync`（~125 行）
- `main/MenuHandler`（CLI，applyCurrentAccount 内）

### 2.2 资源包覆盖（`auth/offline/OfflineSkinPack.java`）

- **产物**：`Starlight Skin.zip` 写入生效游戏目录的 `resourcepacks/`，并把条目写入 `options.txt` 的 `resourcePacks`。
- **zip 结构**：
  - `pack.mcmeta`：pack_format 按版本映射（1.17 → 7）。
  - 1.19.3+：覆盖 `assets/minecraft/textures/entity/player/{slim|wide}/` 下全部 9 个内置皮肤；
  - 1.6~1.19.2：覆盖 `assets/minecraft/textures/entity/{alex|steve}.png`；
  - 1.6/1.7：64×64 双层裁剪为 64×32；<1.6 跳过。
- **options.txt**：条目 1.13+ 为 `"file/Starlight Skin.zip"`（新式），旧式为 `"Starlight Skin.zip"`；同时**强制写 `pauseOnLostFocus:false`**（1.17+ 失焦暂停会冻结渲染，贴图下载不触发）。
- **清理**：每次启动按需调用，删除 `Starlight Skin.zip` + 遗留 `PCL2 Skin.zip`，并从 options.txt 移除条目。
- **生效目录**：版本隔离开启 → `gameDir/versions/<version>/`，否则 → `gameDir`（与 options.txt 定位一致）。

### 2.3 门面（`auth/offline/OfflineSkinManager.java`）

| 方法 | 作用 |
| --- | --- |
| `resolveUuid(baseUuid, skin)` | UUID 微调（启动参数前调用） |
| `applySkinPack(skin, username, gameDir, version, versionIsolation, vanilla)` | 构建/清理资源包 |
| `loadForLaunch(skin, username)` | 加载皮肤+披风（供档案服务器与代理） |
| `capePngBytes(loaded)` | 披风 PNG 字节（供代理） |
| `capeProxyArgs(proxy)` | 代理 JVM 参数 |
| `profilePropertiesArgs(server, versionId)` | `--profileProperties` 参数对（1.17+，Windows 引号转义） |

## 3. 披风通道转接

### 3.1 本地档案服务器（`auth/offline/LocalYggdrasilServer.java`）

- 仅离线账号**配置了披风**时启动（`capePng == null` 不启动，保持纯 PCL2 机制）。
- 端点：`/sessionserver/session/minecraft/profile/<uuid>`、`/session/minecraft/profile/<uuid>`、`/skin.png`、`/cape.png`、`/`（agent 元数据）。
- 元数据含 `skinDomains:["127.0.0.1"]`（缺失 → 客户端 "Textures payload contains blocked domain"）+ `signaturePublickey`（PEM 格式）+ `feature.skins`。
- `buildProfilePropertiesJson()`：**值数组格式** `{"textures":["<base64 value>"]}`，无 signature（1.17+ 本地玩家 requireSecure=false 不验签；对象数组格式会抛 `UnsupportedOperationException: JsonObject` 崩溃）。

### 3.2 `--profileProperties` 注入（`OfflineSkinManager.profilePropertiesArgs`）

- 1.17+ 本地玩家 skin/cape 直注入：无此参数时本地玩家 profile 永远没有 textures 属性。
- **Windows 引号转义**：`json.replace("\"","\\\"")`——JDK ProcessBuilder 不转义参数内部引号，CreateProcess 会剥掉引号导致游戏 Gson 崩溃（`MalformedJsonException line 1 column 3`）；转义后 Windows 侧还原完整 JSON。非 Windows 不转义。
- 注入点：ForgeLegacyLauncher 的 arguments.game 分支（该版本 JSON 无 `${profile_properties}` 占位符）。

### 3.3 本地披风代理（`auth/offline/LocalCapeProxy.java`）——**披风最终生效通道**

- **原理**：给游戏 JVM 注入 `-Dhttp.proxyHost/-Dhttp.proxyPort/-Dhttp.nonProxyHosts`，让 `CapeUtils.downloadCape` 的 HttpURLConnection 请求先落到本代理；代理识别 `s.optifine.net/capes/<玩家名>.png` 即返回本地披风 PNG（200），其余一律 404（OptiFine 静默忽略）。
- **代理参数**：
  ```
  -Dhttp.proxyHost=127.0.0.1
  -Dhttp.proxyPort=<随机端口>
  -Dhttp.nonProxyHosts=127.0.0.1|localhost
  ```
- **生效前提**：`-Djava.net.useSystemProxies=false` 已在启动参数中（HttpURLConnection 的 http.proxyHost 才生效）；nonProxyHosts 排除本机（档案服务器/皮肤贴图 127.0.0.1 请求不走代理）。
- **生命周期**：与 `LocalYggdrasilServer` 相同——有披风才启动，游戏退出与异常路径一起停（daemon 线程）。

## 4. 三条启动路径接入点（改披风/皮肤必看）

| 路径 | 文件 | 接入位置 |
| --- | --- | --- |
| **GUI 主路径** | `gui/UIGeneralControlClass.java` | `launchMinecraftAsync`：UUID 微调 ~608；`applySkinPack` ~778；披风区块 ~788-830（capeServer 启动 → `-javaagent`+代理参数拼 `config.jvmArgs` → `info.setJvmArgs` 同步快照 → `profilePropertiesArgs` 追加 `info.gameArgs`）；停止 ~981-985（正常）/ ~1022-1028（异常） |
| **服务路径** | `service/GameLauncherService.java` | `launchMinecraftAsync`：UUID 微调 ~125；**披风区块在 `buildLaunchInfo` 之前** ~131-151（capeServer → `config.jvmArgs` 追加，天然进入快照）；`profileProperties` 注入 ~195-205；停止 ~486-488 / ~539-541 |
| **CLI 路径** | `main/MenuHandler.java` | 字段 `gameCapeServer`/`gameCapeProxy`（41 行）；`applyOfflineSkinPack` ~819-856（applySkinPack → stopCapeServer → capeServer+proxy 启动 → `config.jvmArgs` 追加）；`buildMinecraftCommand` ~625-632（profileProperties 追加 gameArgs；jvmArgs 在 590-595 拼接）；`stopCapeServer` 双停 |

> 注意 GUI 路径的 `info.setJvmArgs` 是**必须**的：`buildLaunchInfo` 已把 jvmArgs 快照进 info（披风服务器启动之前），不同步回 info 则 Forge Legacy / Vanilla 启动器读到的是不含 `-javaagent` 的旧列表（日志显示有、实际进程没有）。

## 5. 启动参数链路（以 1.17.1-OptiFine_H1 实测为例）

```
java.exe -Xms2048M -Xmx4096M <...> -Djava.net.useSystemProxies=false
        -javaagent:C:\Users\Administrator\.starlight-launcher\authlib-injector.jar=http://127.0.0.1:<port>/
        -Dauthlibinjector.side=client
        -Dhttp.proxyHost=127.0.0.1 -Dhttp.proxyPort=<port> -Dhttp.nonProxyHosts=127.0.0.1|localhost
        net.minecraft.launchwrapper.Launch <...>
        --username 114514 --uuid 6c03... --gameDir D:\新建文件夹 (15)\versions\1.17.1-OptiFine_H1 <...>
        --profileProperties {"textures":["eyJ0aW1lc3RhbXAi..."]}
```

- `-javaagent` 由 `AuthlibInjectorSupport.buildLaunchJvmArgs(apiBase)` 生成（`-javaagent:<jar>=<apiBase>` + `-Dauthlibinjector.side=client`），jar 在 `C:\Users\Administrator\.starlight-launcher\authlib-injector.jar`（1.2.8，SHA256 `9c7f4343e6c82034958ffb48c14a2cb0c85928be7283103ce17da00c6d5a7b10`）。
- 代理参数在 `-javaagent` 之后追加进同一 jvmArgs 串。
- `--profileProperties` 追加进 `info.gameArgs`（GUI/服务路径）或 `parts`（CLI），由 `ForgeLegacyLauncher`（~79-102）arguments.game 分支落到最终命令。
- **完整启动命令打印**：`BaseLauncher.startProcessWithMonitoring` 输出 `[完整启动命令]` 前缀日志（System.out + 日志文件）。
- `--gameDir` 实际是版本隔离目录 `versions/<version>/`（options.txt/saves/resourcepacks/mods 都在该目录）。

- `VanillaVersion.parse(versionId)` / `resolve(gameDir, version)` → major/minor（如 1.17.1 → major=17）。
- 用途：pack_format、贴图路径分支、`--profileProperties` 是否注入（<1.17 不注入，旧版 Main 无该选项会解析失败）。

## 9. 已知死路（勿重试）

1. 资源包 `optifine/cape` + `mcpatcher/cape` 路径 → 1.17.1 jar 无此常量，不生效。
2. 官方源 `download_url` 按驼峰 `downloadUrl` 误判 → 字段名是 `download_url`。
3. GitHub `/releases/latest/download/authlib-injector.jar` → 404（走 `api.github.com/.../releases/latest` 兜底）。
4. 元数据端点缺失 → agent 拒注入（JVM 启动失败）。
5. 缺 `skinDomains` → "Textures payload contains blocked domain"。
6. 裸 X.509 公钥 → "Bad key format"（必须 PEM 头尾）。
7. SHA256withRSA 签原始 payload → 验签失败（必须 SHA1withRSA 签 **value 字段字节**）。
8. `pauseOnLostFocus:true` → 1.17+ 失焦冻结渲染（已强制 false）。
9. **sessionserver 档案 / `--profileProperties` 不会触发任何贴图网络请求**（本地玩家渲染不走 getTextures/registerSkins 网络分支）→ 披风必须走 OptiFine 代理通道。
10. Windows ProcessBuilder 原始引号 JSON → 引号被剥 → `MalformedJsonException` 崩溃（`\"` 转义已修）。
11. 对象数组 PropertyMap → `UnsupportedOperationException: JsonObject` 崩溃（值数组已修）。
