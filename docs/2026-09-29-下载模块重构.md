## 4. mod 提速点清单（对应 PCL 下载提速六机制，pcl_spec.md 第 1-7 节）

| PCL 机制 | 落地类（download.mod） | 关键参数 / 行为 |
|---|---|---|
| ① 多线程分段下载 + 断点续传 + 合并 | `DownloadPiece`、`DownloadFileTask` | 分块独立 `.part` 落 `{gameDir}/.download-cache/{fileHash}/`；首线程不带 Range 探测 Content-Length；动态再分裂（碎片 > 256KB 时于已完成点后 60% 处切分）；单线程串行合并写 `dest.tmp`，Σpiece.done == fileSize 校验后 `Files.move(ATOMIC_MOVE)`；合并失败 3 次 × 500ms 退避后整文件换源重下一轮（Retried 仅一轮）；读缓冲 64KB |
| ② 多源自动切换链 | `DownloadSource`、`DownloadSourceChain`、`HostPolicy` | PCL §2.2 禁用触发条件（RangeNotSupported/416、502/404、DNS/无数据/磁盘不足、403/429 且 bmclapi 例外、从未拿字节且 FailCount ≥ clamp(线程数,5,30)、FailCount > 线程数+2）；首源递增轮转；SourcesOnce 单线程源强制不分块；全部多线程源禁用 → 整文件 Reset 为单线程源重下一轮；HostPolicy 只单线程黑名单（bmclapi/github/modrinth 等） |
| ③ 全局限速 | `GlobalSpeedLimiter` | 全局令牌桶单例：100ms 滴答补充 bytesPerSecond/10；`acquire` park 16ms 自旋；`setLimit(-1)` 不限速；低限 256KB/s 作为加速触发线（一期固定，不自适应抬升，二期再优化） |
| ④ 统一下载队列 / 调度 | `DownloadCoordinator`、`InstallPlan`、`PlanStage`、`LocalFileReuse`、`MetaDiskCache` | 全局单例：线程池取 `DownloadSettings.getDownloadThreads()`（1~16）、按目标路径 ConcurrentMap 去重、20ms 播种循环、100ms 速度统计；InstallPlan 阶段加权进度（下载阶段权重 60~80%）；LocalFileReuse 按同相对路径+大小+SHA1 复用本地已有文件（每 40 文件一线程、上限 8）；MetaDiskCache 小 JSON 按 URL 缓存 TTL 1 天（大文件/分块不缓存） |
| ⑤ 失败重试 + 熔断 | `RetryPolicy`、`RangeNotSupportedException`、`SourceDisabledException` | 连接超时自适应 `min(max(历史平均耗时, 15s) × (1+failCount), 30s)`；慢速掐线（两包间隔 > 5s 且不足约 1KB 且非单线程源 → 断开重连）；与 `util.MirrorCircuitBreaker` 域名级熔断两级并存串联（请求前先问 allowMirror 再问源 disabled） |
| ⑥ 文件校验 | `FileVerifier` | 大小 + Hash 校验（MD5 32 位 / SHA1 40 位按长度自动识别；expectedSize=-1 不校验大小）；IsJson 括号配平轻校验 |

**复用不重写**：`download.engine.HttpDownloadEngine`（公开 HTTP_CLIENT / HTTP_CLIENT_FALLBACK / safeUri / sanitizeUrl）、`util.MirrorCircuitBreaker`、`download.source.DownloadProvider` 及三实现、`download.DownloadSettings`。

## 6. 实现中的权衡记录（执行中自主决策，理由在此备案）

1. **DownloadPiece 自编排 Range 请求**：`HttpDownloadEngine.sendFollowingRedirects` / `downloadRange` 为 private，无法直接复用；DownloadPiece 基于公开的 `HTTP_CLIENT` / `HTTP_CLIENT_FALLBACK` / `safeUri` / `sanitizeUrl` 自行编排分块请求（含 5 跳重定向跟随、UA 常量自管，不 import newui）。
2. **播种循环一期简化**：pcl_spec 的"准备中线程数 ≤ 下载中线程数"细化门控，一期在 `DownloadFileTask.tryBeginThread()` 内部统一做 HostPolicy / SourcesOnce / 碎片大小过滤，未单独暴露准备/在跑线程数对比接口；二期可在 `DownloadCoordinator.seedTick` 补充严格门控（注释已标注）。
3. **UpdateDownloader 取消语义**：为保持原「取消即静默清理、不弹错误」UX，取消时返回 false 而非抛异常；真实网络失败仍抛 IOException。
4. **DownloadService.threadCount 兼容占位**：JUDGE-2 后签名保留但参数不再参与线程调度（原 MultiThreadDownloader 已废弃），中文注释说明。
5. **ModsApi 6 文件归属补做**：原 6 个 agent 职责表未覆盖 ModsApi（QUERY 类）对 DownloadProvider 的 import 引用，编译前由调用方导入 agent 补做修正（含 ModSearchQuery javadoc 全限定名）。
6. **反向 import 闭环**：TerracottaDownloader 迁移后新增 5 个 terracotta 包 import（Manager/Lifecycle/Metadata/State/StatePoller）；InstallEngine 迁移后新增 `version.VersionDownloadService` import；TerracottaBundleStub 迁移后新增 `download.task.AbstractTerracottaProvider` import（引用其嵌套 DownloadContext/Status）。
7. **无需改动的确认**：CacheManager（仅 gson/nio/并发依赖）、TerracottaStatePoller（仅 profile 包）、MultiplayerPage（通配符只用到未移的 TerracottaState/Manager）。
8. **既有代码保护**：TerracottaDownloader 第 53 行历史乱码注释属 HEAD 基线内容，未触碰；UpdateCoordinator 的 sourceHint 镜像提示、UIGeneralControlClass 的 installJavaAsync setOutput 注入为用户既有改动，原样保留。
