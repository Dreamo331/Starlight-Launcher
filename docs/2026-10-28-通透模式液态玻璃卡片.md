# 通透模式：卡片背景改用液态玻璃渲染

> 2026-10-28 · 设置 → 个性化 → 主题与背景 → 通透模式

## 一、需求

设置里新增一个「通透模式」开关。开启后，卡片（`settings-card` / `settings-card-stacked` /
`toolbar-card` 这一族）的背景不再用 CSS 的半透明色块，而是用 `references/liquid-glass` 里那套
**真的去读背后像素**的渲染：拍一张背景快照 → 降采样模糊 → 每张卡片按圆角 SDF 采样、着色、
加边缘高光与投影。**关闭时仍然是原来的 CSS 卡片**，两套渲染方式并存，切换即生效。

## 二、唯一开关文件

**改功能只改这一个文件：** `src/main/java/com/example/starlight/newui/ui/GlassFeature.java`

| 字段 | 作用 |
|---|---|
| `ENABLED` | 总开关。false → 设置页不出现开关卡片、卡片不装玻璃、计时器不启动（实现类也不会被加载） |
| `SHOW_TOGGLE` | 只藏界面开关：功能仍按 `DEFAULT_ON` / 配置里的值生效（调试时强制开/关用） |
| `DEFAULT_ON` | 配置里还没有这个键时的默认状态 |
| `CONFIG_KEY` | 配置键 `GlassMode`（`starlight-client.ini`，已登记 `ConfigManager.CLIENT_KEYS`） |
| `RADIUS` / `BLUR` / `SPECULAR` / `EDGE_WIDTH_RATIO` | 观感：圆角、模糊、高光、边缘带宽 |
| `TINT_ALPHA_LIGHT` / `TINT_ALPHA_DARK` / `BRIGHTNESS_*` / `SATURATION_*` | 着色：浅色/深色两套浓度、明暗、饱和度 |
| `HOVER_TINT_BOOST` | 悬停时额外加的着色 |
| `MAX_RENDER_SCALE` / `PIXEL_BUDGET` / `SETTLE_MS` / `LAG_MS` / `IDLE_TICKS` | 性能：快照比例上限、像素预算、两档防抖、空闲熄火帧数 |

**开关的整块 UI 也在这个文件里**（`maybeAddToggle(ctx, page)`）：`ThemePage` 只留一行调用，
所以"这个功能长什么样、什么状态、怎么切换"全在一处。标题/说明文字走 i18n
（`theme.t0052` / `t0053` / `t0054` / `t0055` / `p0052`），中英文各一份。

### 编译期不参与构建

Java 没有预处理器，真正的「不编译」用 Maven profile：

```powershell
mvn -Pno-glass clean package     # 整个 newui.glass 包不参与编译
```

`GlassFeature` **不直接引用**那个包里的任何类型（实现类通过反射解析），所以排除后工程照样编译，
运行时只打印一行 `[Glass] 通透模式实现未参与编译（-Pno-glass），功能已跳过`，其余全部空转。

实测：默认构建 391 个源文件；`-Pno-glass` 构建 384 个，`target/classes/.../newui/glass/` 里没有任何 `.class`，
运行期 `GlassFeature.available() == false`、`liveCount() == 0`、装玻璃/装饰页面/切开关都是空操作。

## 五、覆盖哪些卡片

`GlassCards.CARD_STYLES` 是一张白名单，`GlassCards.decorate(page)` 在**每次切页时**把整页走一遍，
命中的节点自动装上玻璃（已装过的按卡片属性键跳过）。白名单是「整张卡片」级别的：

| 样式类 | 用在哪 |
|---|---|
| `settings-card` / `toolbar-card` | 设置页与下载页工具条（`PageKit` 造卡） |
| `home-card` / `home-card-left-item` | 首页左栏三块 + 右栏各段 |
| `vset-card` | 版本独立设置页 |
| `account-card-shell` | 账户页 |
| `gamedir-panel` | 游戏目录页 |

**不收**列表行 / 虚拟化单元格（下载页的版本行是 `ListView` 的 `list-cell`，资源页的条目同理）：
它们是上千行里被复用的一格，不是「一张卡片」，而且逐格采样没有意义。

遍历要单独处理 `ScrollPane.getContent()` / `TabPane` 的页签内容 / `TitledPane.getContent()` ——
这些东西不在 `children` 里（在皮肤里），漏掉就会出现「首页右栏、版本独立设置页整页没有玻璃」。

## 六、和参考实现不一样的地方

1. **背景不再是照片，是窗口截图。** 参考实现的 `SceneBackdrop` 画死一张照片；这里每刷新一次就
   把「窗口去掉玻璃卡片之后的样子」拍成像素缓冲（`Node.snapshot`），所以壁纸、主题渐变、
   侧边栏、标题栏都能被折射到，看到的和读到的是同一批像素。
2. **玻璃层是卡片内部一枚不参与布局、也不撑大卡片的 `ImageView`。** 参考实现自带 `GlassPane` 容器，
   但启动器里很多页面先 `PageKit.settingsCard(...)` 拿卡片、之后再 `card.getChildren().add(...)`
   挂控件，包一层容器会把这些调用点全改掉。改用 `managed=false` 的子节点，再用
   `ImageView.setViewport(...)` 把渲染缓冲四周的 `MARGIN` 裁掉：
   **布局尺寸必须严格等于卡片本身**，否则设置页会被撑高 24px、撑宽 48px（滚动区、留白全跟着歪）。
3. **卡片不可拖动。** 参考实现的 `GlassPane` 是一块能拖着走的演示卡片；这里的卡片必须钉死。
4. **拍快照时用 opacity=0 藏卡片，而不是 `setVisible(false)`。** 不可见节点不参与父节点的 bounds，
   快照又会在内部强制走一遍布局，滚动区据此就会认为内容变矮、把滚动位置夹回去。
5. **刷新是防抖的，不是每帧。** 每帧只比对「位置 / 尺寸 / 不透明度 / 主题」，变了才在
   `110ms` 后拍一次快照重画；悬停这类不改背景的变化只重画那一块。安静 1.5 秒后计时器自己熄火。
6. **只拍卡片的并集矩形。** 整窗 1165×722 @1.25 快照约 70–85ms，只拍卡片区域（约 974×480）
   只要 28–45ms；采样比例封顶 1.0（玻璃内部本来就是模糊背景，拍更清晰没有意义）。
7. **滚出窗口的卡片不采样。** 长设置页里看不见的卡片一个像素都不显示，却要照付 CPU。
8. **`BackdropSource` 加了一个开关 `needsImage()`。** 参考实现的背景本身要画到屏幕上；启动器里
   画背景是场景图自己的事，所以关掉那次全屏 `setPixels`。这是移植时唯一改动引擎代码的地方。

## 七、观感参数

以参考卡片的 `Panels.referenceCard()` 为基准，按「卡片更矮、背景更平缓」重调：

- `radii`：统一 12（一堆卡片用不对称圆角会显得互相不是一套东西）
- `blur(9)`、`saturation` 1.18 / 1.12（浅色 / 深色）
- `refraction(0)` + `chroma(0)`：参考实现明确要求两者同时归零，否则边缘会像贴了另一张图
- `turbulence=0`：整套流程里最贵的一项（每像素 3 层噪声），卡片数量多，关掉省几十毫秒
- `edgeWidth`：跟卡片高度收（`h × 0.28`，10–26px）。参考的 40px 是按 168px 高的示范卡片定的
- 着色浓度：浅色白 0.52 / 深色黑 0.62。注意渲染器里还会乘一个「主体/边缘」系数
  （`0.60 + 0.40 × 边缘权重`），玻璃中心实际只取标称值的 60%，所以数要按中心效果倒推；
  参考卡片标 10%，那是压在照片上的示范值，压不住启动器里的文字
- 深色主题额外 `brightness -0.10`：深色主题的文字是白的，玻璃底下若是亮壁纸，白字会糊掉

## 八、实测（Windows 10 / JDK 17 / 窗口 1166×723）

| 场景 | 耗时（快照 + 采样） |
|---|---|
| 首次开启（含 JIT） | 200–240ms，一次性 |
| 滚动停止后重画 | 53–95ms（快照 28–45ms + 采样 15–55ms），卡片越多越久 |
| 首页 9 张卡片 | ~240ms 首次，之后 ~65ms |
| 悬停（只重画脏卡片） | < 10ms |
| 关闭状态下 | 0（`GlassCards.attach` 直接返回，卡片一个字节都不多） |

排版代价：**0**。开/关两种状态下滚动区内容的 `boundsInLocal` 完全一致（实测 914.7×1138.7），
滚轮、滚动位置、滚动范围都不受影响。

`-Dstarlight.glass.debug=true` 会把每次刷新的耗时、视口尺寸与主题状态打到控制台。

## 九、同一轮修掉的「页面多出来 / 滚不动 / 下方没有圆角」

现象：设置页底部被切平、没有圆角，内容没显示全却滚不动。查下来**不是玻璃层的问题**，
而是窗口尺寸本身：

1. `ConfigManager.CLIENT_KEYS` 里漏登记了 `WindowWidth` / `WindowHeight`，窗口大小从来没被存下来
   （`saveWindowState` 每次都写，`saveClientConfig` 每次都丢）；
2. 于是每次启动都走「没给尺寸」的分支 —— JavaFX 会**按场景首选尺寸**自己定窗口大小，
   而首页内容的 pref 高度上千（本机实测窗口 1936×1119）；
3. 窗口再按上次的 `WindowY=326` 摆出来 → 底边 1445 超过屏幕可视底边 1400，
   **窗口底部（连同圆角）跑到屏幕外**，看起来就是「页面下方没有圆角」；
4. 同时设置页的滚动视口被撑到 1082，而页面内容只有 644 —— 明明内容没看全，也确实没有可滚的东西。

修法（`JavaFXLauncher` + `ConfigManager`）：

- `WindowWidth` / `WindowHeight` 登记进 `CLIENT_KEYS`，用户拖动过的窗口尺寸从此能存下来；
- 新增 `clampWindowToScreen(stage)`：`show()` 之后把窗口尺寸裁到可视区域（留 40/60px 边距），
  并把位置夹回来，保证整窗在屏内、圆角看得见；最大化 / 全屏时跳过。

实测（本机 2560×1400 可视区）：窗口 1937×1119，位置 y 从 326 被夹到 273，底边 1392 ≤ 1400。

## 十、已知限制

- 玻璃之间不互相折射（A 读不到 B 的结果），要做得走多趟渲染；
- 滚动过程中不重画（沿用上一帧的玻璃图），停下来才重拍 —— 这是刻意的，否则惯性滚动会一直烧 CPU；
- 纯 CPU 采样，适合十几张卡片；整屏几十块该上 shader；
- 背景若有持续动画（帧生成器那种实时曲线），玻璃不会跟着每帧更新；
- 列表行（下载页版本行、资源页条目）不参与玻璃：它们是虚拟化复用的 `list-cell`，不是卡片；
- 卡片里若有写死白底的行内元素（首页「快速进入存档」的存档行、版本设置的行），
  在玻璃上会显得比周围白一截，属于既有样式，本次没有动；
- 首页是「整页不滚动」的仪表盘：屏幕可视高度小于首页内容高度时（约 1100 逻辑 px 以下），
  窗口被夹到屏幕内之后首页底部会被切掉且不能滚 —— 这是窗口几何的老问题，本次只保证
  窗口不再跑到屏幕外，没有把首页改成可滚动页。

## 十一、没有动的东西

- 没有新增依赖（纯 JavaFX + 移植代码）；
- 没有新增网络请求、没有新增数据收集 → 隐私政策、第三方声明无需变更；
- 没有改动任何法律文本，因此不需要重新存证。
