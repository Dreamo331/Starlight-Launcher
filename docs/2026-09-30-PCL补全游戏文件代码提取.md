## 2. 调用关系（补全主链）

```
McLaunchStart (ModLaunch.vb)                      ← 启动时执行
  └─ DlClientFix(Instance, CheckAssetsHash, DownloadAssetIndexInBackground)     [ModDownload.vb]
       ├─ McLibNetFilesFromInstance(Instance)     分析缺失支持库        [ModMinecraft.vb]
       │    ├─ DlClientJarGet(Instance, True)     主 Jar 下载信息       [ModDownload.vb]
       │    ├─ McLibListGet(Instance, False)      库列表                [ModMinecraft.vb]
       │    │    └─ McLibListGetWithJson(...)     JSON 解析/去重        [ModMinecraft.vb]
       │    └─ McLibNetFilesFromTokens(...)       NetFile 化/多源 URL   [ModMinecraft.vb]
       └─ McAssetsFixList(Instance, CheckAssetsHash, ...)  缺失资源文件  [ModMinecraft.vb]
            └─ McAssetsListGet(Instance)          索引 objects 解析     [ModMinecraft.vb]
                 └─ McAssetsGetIndexName(...)     索引名（含继承）       [ModMinecraft.vb]
       （另：DlClientAssetIndexGet → McAssetsGetIndex 负责索引下载信息，支持后台更新）
```

## 5. 值得关注的实现细节（迁移时参考）

1. **主 Jar 并入库列表**：`McLibListGet(IncludeMainJar=True)` 把客户端 Jar 作为库条目一并补全（`ModMinecraft.vb:1904-1942`），与 Java 侧 `completeVersionJar` 单列第三阶段的做法不同。
2. **AssetIndex 后台更新**：`DlClientFix` 支持 `DownloadAssetIndexInBackground=True` 时每日一次后台刷新索引，主流程只补缺失资源（`ModDownload.vb:120-148`）。
3. **跳过校验开关**：`ShouldIgnoreFileCheck` 由版本级设置 `VersionAdvanceAssetsV2` / `VersionAdvanceAssets` 控制（`ModMinecraft.vb:2214-2216`），对应 Java 侧 `VerifySettings.FastVerify` 的语义但粒度在版本级。
4. **虚拟/重映射资源**：`McAssetsListGet` 对 `virtual` 索引映射到 `assets/virtual/legacy`、`map_to_resources` 映射到资源目录（`ModMinecraft.vb:2319-2328`），对应 Java 侧 `handleVirtualResources`。
5. **校验策略**：`McAssetsFixList(CheckHash=True)` 把 hash 检查推迟到下载阶段借助多线程完成；`CheckHash=False` 时则先按存在性+大小过滤（`ModMinecraft.vb:2347-2378`）。
6. **多镜像 URL 构造**：`McLibNetFilesFromTokens` 对 maven 库按 `DlSourcePreferMojang` 决定镜像优先还是官方优先（`ModMinecraft.vb:2165-2173`）。
