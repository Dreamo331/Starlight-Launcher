# 星光启动器 Starlight Launcher · 安全与合规说明

**版本 1.0 · 更新日期：2026 年 10 月 20 日**

> 本说明面向**平台审核员、应用商店审核、家长与监管机关**，用可核查的事实回答两个问题：**这个启动器会不会偷数据、会不会诱导消费？** 每一条都能在源代码中找到对应实现。
>
> 本文是[免责声明](免责声明.md)与[隐私政策](隐私政策.md)的技术佐证，不构成新的权利义务约定。

## 一、三十秒结论

| 审核关注点 | 结论 | 佐证 |
|---|---|---|
| 是否内置充值/支付 | **否** | 源码中不存在支付、充值、订单、代收相关实现；无任何支付 SDK 依赖 |
| 是否从服务器抽取分成 | **否** | 无分账、无推广位逻辑、无返点配置；服务器地址由用户自行输入 |
| 是否收集个人信息 | **开发者侧不收集** | 无统计 SDK、无埋点上报、无设备指纹；仅本地读写配置。你主动使用的第三方服务（微软登录、社区、AI）按其自身政策处理 |
| 是否上传本地文件 | **仅在主动点击"上传日志"时** | 上传后展示链接与二维码并留痕，可在"日志记录"页撤回删除 |
| 是否含广告 | **否** | 界面无广告位，无广告 SDK 依赖 |
| 是否自动更新 | 是（可关闭） | 只比对版本号，不上传任何用户数据 |
| 是否静默连接第三方 | 仅下载与更新所需 | 目标域名为 Mojang、BMCLAPI、Modrinth、CurseForge 等公开源，见[第三方声明](第三方声明-Third-Party-Notices-中文.md) |
| 是否会代替用户搜索 | **否** | 顶部搜索胶囊只在本地拼 `cn.bing.com` 结果页地址后交给系统默认浏览器；启动器不发起搜索请求、不解析结果页 |

## 二、数据流拓扑（本地优先）

```
                    ┌──────────────────────────────┐
                    │        你的电脑（本地）        │
                    │                              │
  游戏目录 .minecraft ◄──┤ 启动器：解析版本、拼装 JVM 参数 │
  配置 ~/.starlight/   ◄──┤ 账号、设置、缓存、日志         │
                    │                              │
                    └───────┬──────────────┬───────┘
                            │ 你点击下载    │ 你点击"上传日志"
                            ▼              ▼
                 Mojang / BMCLAPI      日志分享服务
                 Modrinth / CurseForge  （可撤回删除）
```

**关键设计：** 启动器本身**没有后端业务服务器**。除更新检查与可选的社区模块外，所有网络请求都是为了完成你此刻的操作（下载游戏、登录、查模组）。

## 三、日志上传的边界（最容易被误解的功能）

| 项目 | 事实 |
|---|---|
| 触发方式 | **只能由用户点击"上传日志"按钮**触发，无自动上传、无后台定时上报 |
| 上传内容 | 单个日志文件（崩溃报告 / `latest.log` / 启动器日志），最多读取尾部 4 MB |
| 目标地址 | 默认 Logshare 公共接口（`api.logshare.cn`），可由运维配置替换 |
| 上传前提示 | 界面展示"日志已上传"结果页，含链接与二维码，并记录本次上传 |
| 撤回 | "日志记录"页提供**撤回删除**，调用服务端的删除接口（需上传时返回的凭证） |
| 敏感信息 | 日志可能含 Windows 用户名、路径、服务器地址，**由用户自行判断是否上传** |

> **建议增强（当前未实现）：** 在上传前增加一次"本次将上传：文件名 / 大小 / 目标地址"的确认弹窗，可进一步降低"静默上传"的误解风险，见第八节第 3 条。

## 四、账号与令牌

1. 微软账号登录走**设备码（Device Code）流程**，令牌由用户本机保存，不经任何中间服务器。
2. 令牌以明文或轻量混淆形式存于 `~/.starlight/`。这是**开源启动器行业的通行做法**，但仍建议用户：不要在公用电脑上保存账号，开启系统登录密码。
3. 本项目**不收集**账号密码，也无法通过本项目登录你的微软账号——除非你亲自完成授权。

## 五、插件系统的安全边界

| 边界 | 实现 |
|---|---|
| 监听地址 | `127.0.0.1`（仅本机回环），局域网其他设备无法访问 |
| 鉴权 | 插件须先握手换取 `session_token`，之后每个数据请求携带 `X-Session-Token` |
| 权限 | 插件只能调用启动器**已声明开放**的 API，无法直接执行任意系统命令 |
| 责任 | 插件行为由插件作者负责；用户应只安装来源可信的插件 |

### 5.1 游戏 JVM 的字节码注入（披风补丁 agent）

离线账号在 OptiFine 客户端里显示自定义披风，需要在游戏启动参数里加一条 `-javaagent`。
这是本项目**唯一**会对游戏 JVM 做字节码改写的场景，边界如下：

| 项目 | 实现 |
|---|---|
| agent 来源 | 本项目自行编写的 `cape-url-patch-agent.jar`（`tools/agent/CapeUrlPatchAgent.java`，MIT），随 EXE 作为内置资源分发，首次使用时释放到 `~/.starlight/` |
| agent 做了什么 | 仅在常量池里把 `http://s.optifine.net` 前缀替换为 `http://127.0.0.1:<本地端口>`；不加载额外代码、不联网、不读写用户文件 |
| 数据流向 | 披风下载由公网 OptiFine 服务器改为**本机回环**，不向外发送任何数据 |
| 兜底下载 | 仅当 EXE 内缺失该内置资源时才联网补下载，且**必须**通过 SHA-256 校验，不符即丢弃并跳过披风注入 |
| 触发条件 | 只对**离线账号且配置了披风**的启动生效；正版账号与无披风账号完全不注入 |
| 失败处理 | 任一步失败都只跳过披风功能，不阻断启动 |

## 六、未成年人保护的可核查措施

1. 首次启动与"关于"页面提供[免责声明](免责声明.md)入口，明确**禁止未成年人未经监护人同意向第三方服务器消费**。
2. 软件**不具备**收款能力，因此不存在"诱导未成年人向本软件付款"的可能。
3. 若发生第三方服务器内的大额消费，本软件**无法**也不会代收、代退——因为它从未接触该笔资金。
4. 建议监护人为孩子的设备开启支付验证、关闭免密支付。

## 七、应对"连坐"风险的设计

第三方服务器暴雷（跑路、停服、卷款）时，常见的指控是"启动器与该服务器有合作、从中抽成"。本项目的抗辩基础由三层构成：

**第一层：代码事实。** 无支付接口、无分账逻辑、无服务器推广位——可审计、可复现。

**第二层：协议事实。** [用户服务协议](用户服务协议.md)第 5.1 至 5.3 条、[免责声明](免责声明.md)第二节、[许可协议](LICENSE-ZH.md)第 8.2 至 8.3 条，均明确：第三方服务器内的行为是用户与该服务器运营方之间的独立契约。

**第三层：告知事实。** 免责声明在首次启动时弹窗展示，用户点击"同意"方可继续（建议实现，见第八节）；日志上传等潜在敏感操作均有独立确认。

> **重要提示：** 法律抗辩的强度取决于**证据**，而不是文字。建议保留：发布包的哈希值、Git 提交记录、弹窗同意日志（本地留存即可）、以及任何收到投诉后的处理记录。

## 八、建议的产品侧落地（可选）

为了让上述文档**真正产生法律效力**，建议在代码中补上以下最小实现：

1. **首次启动同意弹窗**：展示[免责声明](免责声明.md)摘要与完整链接，用户点击"我已阅读并同意"后写入本地标记文件（如 `~/.starlight/consent.json`，记录版本号与时间戳）。
2. **关于页面入口**：在"设置 → 关于"增加"用户协议 / 隐私政策 / 免责声明 / 开源许可"四个链接，指向随包分发的本地文件或官网。
3. **日志上传二次确认**：上传前弹窗列出"本次将上传：文件名、大小、目标地址"，避免静默上传的误解。
4. **版本化同意**：免责声明重大修订时提升版本号，触发重新确认。
5. **服务器黑名单（配合[用户服务协议](用户服务协议.md)第 5.8 条）**：当前代码**没有**服务器地址黑名单机制。若决定把 5.8 条的"有权阻断"落成实际功能，最小实现是：内置一份可远程更新的屏蔽列表（域名/IP 前缀），在启动前的服务器地址解析处拦截并提示"该服务器已被屏蔽"。**注意：** 该条只写了"有权"而非"有义务"，因此不实现也不构成违约；一旦实现，请在界面中提示屏蔽依据，避免被质疑为无理由区别对待。
