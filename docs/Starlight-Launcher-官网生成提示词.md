## 1. 一句话产品定位

**Starlight Launcher（星光启动器）是一个完全用 Java 17 + JavaFX 从零自研的 Minecraft 启动器**，界面与逻辑均不基于任何现成启动器外壳，提供「启动游戏 + 管资源 + 找模组 + 拉朋友联机 + 出事能诊断」的完整闭环，并内置一套可扩展启动器自身能力的 **MOD 插件系统**。

## 3. 功能特性（按官网模块分组，可直接作为分区）

### 🚀 启动与账号

- **微软正版登录**：设备码（Device Code）授权流程，无需手动填密码
- **离线账号 / 外置登录**：兼容 authlib-injector（LittleSkin 等第三方皮肤站）
- 多账号管理、头像自动获取、最近游玩记录、静默登录
- 启动前 **并行资源准备 / 并行文件校验**，支持跳过校验提速
- JVM 预热、内存参数、窗口尺寸、启动前 / 后自定义命令、JVM 参数自定义
- **版本独立设置**：每个游戏版本可单独覆盖全局配置（内存、Java、窗口等）

### 📦 版本与下载

- 原版版本清单下载与安装（自动补全 assets / libraries / natives / 客户端 jar）
- 加载器一键安装：**Forge · NeoForge · Fabric · Quilt · OptiFine**（含 Fabric API / QSL）
- **整合包安装**：解析 CurseForge / MCBBS 清单并递归安装，自动处理 `inheritsFrom` 继承链
- **多线程分块下载 + 断点续传**，下载任务面板支持暂停 / 取消 / 重试 / 限速
- 下载源可切换：**Mojang 官方 / BMCLAPI / MCBBS 镜像**，含镜像熔断与自动回退
- 下载中心六大分类：游戏版本 → 模组 → 整合包 → 数据包 → 资源包 → 光影包

### 🔍 资源与模组

- **Modrinth + CurseForge 双源**模组搜索，内置中文词典翻译（MC 百科 / HMCL 词库）
- 模组安装、更新、启停、批量管理，自动匹配游戏版本与加载器
- 整合包 / 资源包 / 光影包 / 存档 / 截图 / 崩溃报告集中管理

### 🌐 联机（注意当前可用状态）

- **陶瓦联机（Terracotta）**：基于 ice4j 的 ICE / NAT 穿透，节点列表自动获取 —— **可用**
- **SLAN 联机**：局域网房间（邀请码 / 联机密码） —— **可用**
- Minecraft 局域网组播监听，自动发现同网段房间 —— 可用
- FRP 中继联机 —— **界面保留入口，功能暂未开放**，文案上不要当作可用卖点

### 🎨 个性化与无障碍

- 浅色 / 深色主题跟随、自定义背景图、仿 macOS 三点式窗口按钮
- 侧边栏显隐、导航动效、滚动速度与平滑度调节、骨架屏加载
- 全套**矢量图标**（Lucide 风格 SVG 自绘，非 emoji）
- **辅助功能页**：高对比度、停用惯性滚动
- **色盲辅助**：可调用外置覆盖工具做实时色彩矫正，并记忆每套配置

### 🩺 崩溃诊断

- 错误码 + 崩溃原因 + 环境信息 + 关键日志的**结构化展示**
- 日志上传生成**二维码**分享、日志导出 zip、一键复制错误
- **AI 诊断**：调用大模型分析崩溃日志，结果以 Markdown 渲染在面板内

### 🧩 其他亮点

- **网络检测**：Mojang / BMCLAPI 等目标连通性与测速
- **内存优化页**：JVM 参数优化建议与一键应用
- **帧生成**：联动 Lossless Scaling 实现游戏帧生成，系统托盘快捷切换倍率
- **星光 MC 社区**：内置社区登录、签到、帖子与评论
- **启动器 MOD 插件系统**：第三方可扩展启动器自身能力
- CLI / 控制台模式（`--console`），可用于脚本化启动

## 4. 可用的技术亮点（给「技术向」分区用）

这些是真实实现，适合放在「为什么选择我们 / 技术细节」折叠区：

- **从零自研**：不基于任何现成启动器壳，UI 与逻辑全部自写
- **插件沙箱**：启动器 MOD 以**独立子进程**运行（`java -jar`），与主程序不共用 ClassLoader，崩溃互不影响；主程序通过**本地 HTTP API**（约 30 个 `ApiProvider`）向插件暴露数据，插件自主实现 UI
- **下载通道**：多源候选 → 镜像熔断（2 次失败 / 60s 窗口）→ 多线程分块 + 断点续传 → sha1 / 大小校验落盘
- **启动流程**：继承链合并 → 库去重 → 双模式资源准备（并行 / 串行）→ 原生库处理 → 进程启动 → 游戏窗口检测（HMCL 轮询新 Java 进程 + PCL 日志特征双阶段并行）
- **原生镜像**：GraalVM Native Image 打包为无 JRE 依赖的单文件 EXE，内置 GPU / 软件渲染多套 Prism 渲染管线兜底
- **便携部署**：所有运行时数据集中在工作目录 `Starlight-Launcher/`，卸载 = 删除该目录，不污染系统

## 7. 视觉风格要求

- **基调**：现代、干净、偏开发者工具的克制感；不要花哨的霓虹赛博朋克，也不要幼儿化卡通。
- **主题**：以蓝色系为主色（参考 `#3B82F6` 主色、`#2563EB` 深色悬停态、`#60A5FA` 点缀），搭配中性灰（`#1F2937` 深字、`#6B7280` 次字、`#F9FAFB` 浅底）。
- **深色模式**：建议提供。深色背景可用深蓝层次（如 `#0D2137` → `#1E293B`）。
- **圆角与阴影**：卡片圆角 12~16px，柔和阴影，避免重投影。
- **排版**：中文无衬线（系统字体栈或思源黑体 / 霞鹜文楷类），标题字重 700，正文 400，行高宽松。
- **图标**：统一线性矢量风格（Lucide 风格），**不要混用 emoji 当功能图标**。
- **动效**：轻微、有目的 —— 滚动淡入、卡片悬停微抬升、导航滑动指示条；不要全屏粒子动画。
- **响应式**：桌面 / 平板 / 手机三档；导航可折叠，功能网格自适应列数。
- **无障碍**：对比度达 WCAG AA，可键盘导航，图片带 alt 文本，尊重 `prefers-reduced-motion`。
