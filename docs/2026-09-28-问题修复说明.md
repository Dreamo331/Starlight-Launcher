# Starlight Launcher 问题修复说明

> 日期：2026-09-28 ｜ 适用范围：本仓库当前工作区
> 本文档记录本轮修复的 4 个问题、改动文件、行为变化与验证结果。

## 一、修复的问题

### 1. exe 目录下异常创建 `null` 文件夹，启动器默认选中 `null` 目录、配置卡片显示 `null`

**根因**：INI 配置保存逻辑会把「缺失的键」或「值为 null 的键」写成字面量 `key=null`。
- `UIGeneralControlClass.saveConfig` 中原写法 `config.getOrDefault(key, config.get(key))`
  在调用方 map 里没有该键时返回 `null`，于是把 `GameDir` 等字段写成 `GameDir=null`；
- 下次启动读到 `GameDir=null`，`Path.of("null")` 作为游戏目录 → 在 exe 目录下创建 `null` 文件夹，
  插件 API 服务（PluginApiServer 写端口文件）也会往 `null/` 里写文件；
- 游戏目录下拉框 / 卡片显示来自该配置值，于是出现「默认选中 null 文件夹」「卡片显示 null」。

**修复**：
- 三处配置写入器（`UIGeneralControlClass.saveConfig`、`ConfigManager.saveConfig`、`MenuHandler.saveConfig`）
  全部改为：值为 null 时**保留原行 / 写空值**，绝不写出 `=null`；
- `GameDirManager` 把所有字面量 `"null"`（或空白）路径视为未配置：
  - `activePath()` 遇到 `GameDir=null` 回退到默认目录 `.minecraft`；
  - `load()/listFromConfig()/split()/store()` 剔除 `null` 条目；
- `JavaFXLauncher.runBackgroundInit` 解析插件目录时对 `null`/空值回退 `.minecraft`（防御旧配置残留）。

**效果**：已损坏的 `starlight.ini`（含 `GameDir=null`）下次启动自动纠正为默认目录；
不会再创建 `null` 文件夹；卡片与下拉框不再显示 `null`。

### 2. 「打开开源仓库 / 社区 / 赞助」按钮在部分电脑（虚拟机等）不启动浏览器

**根因**：统一走 `java.awt.Desktop.getDesktop().browse()`。在无桌面服务、无默认浏览器关联、
或 GraalVM 原生镜像等受限环境，AWT Desktop 静默失败（方法直接返回 false / 抛异常），表现为「点了没反应」。

**修复**：新增 `util/DesktopOpener`，按平台多级降级打开：
1. Windows：`rundll32 url.dll,FileProtocolHandler <url>`（不依赖浏览器默认关联解析，虚拟机也能用）；
2. `cmd /c start`（macOS 用 `open`、Linux 用 `xdg-open`）；
3. `java.awt.Desktop` 兜底。
同时只放行 `http/https` 前缀，防止把任意字符串交给命令执行。
`LauncherView.openWebUrl / openFile`、`AboutPage`（GitHub/Gitee 仓库按钮）、`CommunityPage`、
`SponsorPage`、`UpdateCoordinator` 全部改用该工具。

### 3. 微软登录卡在「正在获取设备码」

**根因**（两层）：
- 设备码请求没有读超时：网络/代理挂起时 `client.send` 无限阻塞，弹窗永远停在获取设备码；
- 获取到设备码后 `copyToClipboard()` 调用 `Toolkit.getDefaultToolkit().getSystemClipboard()`：
  在无图形/受限环境可能抛 **`AWTError`（Error 而非 Exception）**，
  而 `LoginCoordinator` 只 `catch (Exception)`，异步任务静默死亡 → UI 停在「正在获取设备码」，
  与日志里「POST/200 已拿到 device_code」的现象完全吻合。

**修复**：
- 设备码请求与令牌轮询请求均加 `.timeout(30s)` 读超时，网络异常会进入错误分支而不是无限阻塞；
- `copyToClipboard` 改为捕获 `Throwable`，剪贴板不可用只降级为「请手动输入」；
- `LoginCoordinator` 两处异步块由 `catch (Exception)` 放宽为 `catch (Throwable)`，
  任何 Error 都会把弹窗推进到「获取设备码失败」而非卡死。

### 4. 未安装 Java 时点「启动游戏」：不再闷头启动失败，改为自动安装并配置环境变量

**新增**：
- 启动链路（`UIGeneralControlClass.launchMinecraftAsync` 与 `service/GameLauncherService`）在读取版本信息前
  调用 `JavaEnvironmentManager.ensureJavaForLaunch`：
  - 配置的 Java（含系统默认 `java`）可用 → 直接放行；
  - 不可用（未安装 / 路径失效）→ 自动下载对应版本 JDK（按 MC 版本：`<1.17 → jdk8`、`≤1.17 → jdk17`、`≥1.21 → jdk21`，
    Adoptium 清华/华为镜像）解压到 **`tools/java/`**；
  - 安装成功后：自动定位 `bin/java.exe`、写入 `starlight.ini` 的 `JavaPath`、把 `JAVA_HOME` 与 bin 目录
    写入用户环境变量（`setx`，持久化；失败不影响游戏启动，游戏通过显式 javaPath 运行）；
  - 安装失败 → 明确报错并给出补救路径，不再「继续尝试启动然后莫名失败」。
- 「Java虚拟机与内存」设置页新增两个按钮：
  - **「下载 Java」**：打开官方下载页（adoptium.net），供用户手动安装；
  - **「自动安装」**：一键下载 JDK 17 到 `tools/java`，自动配置路径与环境变量，装完自动选中。

- null 修复冒烟测试（7 项全过）：`GameDir=null` 回退默认目录、`null` 条目剔除、局部保存不写 `=null`、null 值保留原行、首次保存不含 `=null`；

- DesktopOpener 防护测试（5 项）：null/空串/`ftp:`/`cmd.exe` 全部拒绝，仅放行 http/https；
- 待你在虚拟机/新电脑实测项：设备码登录全流程、自动安装 Java 的真实下载解压（约 200MB）、浏览器打开按钮。

## 四、行为说明 / 注意事项

- 自动安装的 JDK 存放于启动器工作目录下 **`tools/java/`**（长期使用文件按约定放 tools）；
- 环境变量通过 `setx` 写入**用户级** `JAVA_HOME` 与 `PATH`（持久化）；游戏进程通过显式 `JavaPath` 运行，不依赖 PATH；
- 若 `setx` 因 PATH 超长等原因失败，仅影响环境变量持久化，不影响本次启动；
- 首次自动安装需要几分钟（下载约 200MB），进度通过启动进度条实时显示，可随时取消。
