# 日志上传 UI 与信息窗口逻辑重写

日期：2026-10-01
现象：日志上传的 UI 与「创建日志上传信息窗口」等逻辑消失——崩溃面板上传日志后只显示状态文本（旧行为：二维码存当前目录 + 用资源管理器打开），不弹分享窗口、不写上传记录；资源页「上传的日志」栏目也不存在。

## 原因

`GameCrashPanel`（崩溃诊断面板）的上传处理被回退/丢失为旧实现：走 `LogService.uploadLogAndGenerateQR`（上传 + 二维码存当前目录 + `LogExporter.openInExplorer` 打开目录），既没有调用 `LogUploadResultWindow`（二维码 %TEMP%\starlight-qr + 地址框复制 + 撤回按钮的分享窗口），也没有调用 `LogUploadStore` 持久化上传记录；`ResourcesPage` 的「上传的日志」导航栏目缺失。

基础组件（`sendlogs.java` Logshare API、`LogUploadResultWindow`、`LogUploadStore`、`LogUploadRecord`）仍完整，是调用链断裂。

## 改动文件

### 1. `src/main/java/com/example/starlight/newui/GameCrashPanel.java`

- 构造器新增 `Window ownerWindow` 参数（上传结果弹窗的 owner，由 LauncherView 传入主窗口）。
- `handleSendLog` 重写为完整链路：
  - `sendlogs.uploadLogFileEx(...)` 上传并拿到 `id / url / token`（Logshare API，支持撤回）；
  - 构造 `LogUploadRecord`（文件名 / 时间 / 文件数 / 字节数）→ `LogUploadStore.add` 持久化；
  - 成功后 `LogUploadResultWindow.show(ownerWindow, record, toast, onDeleted)` 弹出分享窗口（二维码保存在 `%TEMP%\starlight-qr`，不打开资源管理器；地址框带复制按钮；撤回按钮可删除线上日志并移除本地记录）；
  - 失败恢复按钮并显示错误。
- 删除旧的 `onSendLogResult`（不再需要 LogService 路径）。

### 2. `src/main/java/com/example/starlight/newui/LauncherView.java`

- `showCrashPanel` 创建 `GameCrashPanel` 时传入 `stage`（主窗口）。

### 3. `src/main/java/com/example/starlight/newui/page/ResourcesPage.java`

- 侧边导航新增分类 **「上传的日志」**（图标 upload）。
- `showResourceContent` 新增 `resource_uploaded_logs` 分支，列出 `LogUploadStore.load()` 的全部记录，每条卡片：
  - 标题：日志文件名；副标题：上传时间 + 文件数 + 链接（截断显示）；
  - 操作：「再次分享」（重新弹出 LogUploadResultWindow 分享窗口）、「复制链接」、「删除」（确认后先尝试 `sendlogs.deleteLog` 撤回线上日志，再移除本地记录；旧版无 id 的记录按 url+time 兜底移除）。
  - 支持搜索（文件名/链接）与分批渲染。

## 验证

- `mvn -o compile`：BUILD SUCCESS（314 源文件）。
- 链路核对：GameCrashPanel 上传 → LogUploadStore.add → LogUploadResultWindow.show 全部接通；ResourcesPage 读取同一存储（`Starlight-Launcher/uploaded_logs.json`），删除/撤回与分享窗口回调联动。
- 未实际点击 GUI（启动器为 JavaFX 桌面程序）；真实上传走 Logshare API 的行为此前已交付并验证。

## 备注

- 未打包 exe（纯 Java 逻辑修复）；`LogService` 与 `UIGeneralControlClass.uploadLogAndGenerateQR` 旧 API 保留（兼容其他调用方），新链路不再使用。
