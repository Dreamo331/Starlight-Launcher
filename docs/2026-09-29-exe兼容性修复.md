# exe 兼容性修复说明（“此应用无法在你的电脑上运行”）

> 日期：2026-09-29
> 状态：已修复并重新打包验证

## 一、现象

双击 `target\gluonfx\x86_64-windows\Starlight Launcher.exe` 弹出 Windows 错误：

> **此应用无法在你的电脑上运行** / 若要找到适用于你的电脑的版本，请咨询软件发布者。

报错在宿主机（Windows 10 专业版 64 位 10.0.19045，Intel i5-10400F，AMD64）与虚拟机上都出现；
**之前打包的 exe 可以正常打开**，本次打包后无法运行。

## 二、诊断过程（证据链）

| 检查项 | 结果 |
| --- | --- |
| 宿主机系统位数 | Windows 10 专业版 64-bit，PS_ENV_ARCH=AMD64 |
| exe 架构（PE machine） | 0x8664 = AMD64 ✅ |
| PE 类型 | PE32+（magic 0x020B），SizeOfOptionalHeader=240 ✅ |
| OS/子系统版本 | 6.0（兼容 Win7 及以后）✅ |
| 节区 | 10 个节全部位于文件边界内，无越界 ✅ |
| 映像范围 | SizeOfImage=0x875B000 恰好覆盖最后一个节 ✅ |
| 导入表 | 33 个标准系统 DLL（kernel32/user32/…）+ MSVC 运行库（VCRUNTIME140 等），宿主机均已安装 v14.51 ✅ |
| 数据目录 | 全部指向合法节区 ✅ |
| 宿主实测 | Start-Process、CreateProcess（`&`）、`cmd /c start` **全部被 Windows 加载器拒绝** |

结论：exe 的 PE 头、节区、导入表**结构全部正常**，但 Windows 加载器仍拒绝 → 问题不在架构，而在**构建流程对 exe 的后处理**。

## 三、根因

`build-single-exe.bat` 第 [7/7] 步调用 `tools\set-metadata.bat`，用 **rcedit-x64.exe** 给 exe 重写图标和版本信息。

GraalVM native-image 生成的 exe 与 rcedit 不兼容：

1. 链接期本身已产生警告 `LNK4078: 找到多个".rsrc"节，它们具有不同的特性(40000040)`（JavaFX 静态库 `glass.lib` 自带资源节 + 图标 `IconGroup.obj` 资源节），这是无害的正常现象；
2. rcedit 在此基础上**重写资源目录**，把旧 `.rsrc` 改名为 `.rsrc1` 并新建自己的 `.rsrc`，资源目录跨越多个属性不同的节（PE 中可见 `.rsrc`/`.rsrc`/`.rsrc1` 三个资源节）；
3. 该结构被 Windows 加载器判为无效映像 → `ERROR_BAD_EXE_FORMAT (193)` → 弹“此应用无法在你的电脑上运行”。

**旧包能打开**是因为之前的打包流程没有跑（或没跑坏）这一步。

### 验证（决定性实验）

用链接日志中的原始 link 命令**跳过 rcedit 重新链接**，得到的新 exe：

```
alive=True（Start-Process 启动 10 秒保持运行，随后测试进程被正常结束）
```

即：同一批编译产物，不跑 rcedit → exe 正常；跑了 rcedit → exe 被拒。根因 100% 坐实。

## 四、修复内容（本次变更文件清单）

| 文件 | 变更 |
| --- | --- |
| `pom.xml` | gluonfx 插件配置新增 `<iconPath>src/windows/assets/icon.ico</iconPath>`：图标由链接器原生嵌入，不再需要 rcedit |
| `build-single-exe.bat` | 第 [7/7] 步改为调用新版 `set-metadata.bat`（安全合并元数据），失败仅警告不中断 |
| `tools\set-metadata.bat` | 重写：不再用 rcedit；改为 `metadata.txt → version.rc → rc.exe → .res → cvtres → .obj → 重链` |
| `tools\apply-metadata.ps1` | 新增：解析 metadata.txt、生成 version.rc（图标+版本合并为一个资源对象）、rc/cvtres 编译、链接到暂存路径成功后覆盖正式 exe |
| `docs\2026-09-29-exe兼容性修复.md` | 本说明文档 |

### 关于元数据（图标 + 版本信息）的安全写入

MSVC 链接器**只接受一个含资源的输入**（glass.lib 的 GlassResources.res / gluonfx 的 IconGroup.obj 已占用），直接追加 `.res` 会报 LNK1241。因此方案为：

1. `apply-metadata.ps1` 读取 `src\windows\assets\metadata.txt`（Key=Value，支持 Icon/FileDescription/ProductName/CompanyName/LegalCopyright/FileVersion/ProductVersion）；
2. 生成 `version.rc`，**把图标（`IDI_ICON1 ICON "…icon.ico"`）与 VERSIONINFO 合并进同一个 .rc**；
3. `rc.exe` 编译为 `.res` → `cvtres.exe` 转为 `.obj`（唯一资源对象）；
4. 用与 gluonfx 完全相同的链接命令重链，**用该 .obj 替换 IconGroup.obj**，输出到暂存路径，成功后才覆盖正式 exe（link 失败会删除输出文件，避免弄丢可用 exe）；
5. 验证：exe 正常启动 + `VersionInfo` 完整读取 + 资源目录含 RT_ICON / RT_GROUP_ICON / RT_VERSION。

> 注：`apply-metadata.ps1` 中 rc.exe / cvtres.exe / link.exe / vcvars64 路径为本机构建环境专用（Windows SDK 10.0.26100 + MSVC 14.51），换机器需相应调整。

### 验证结果（元数据）

- 重链后 exe 141,757,952 字节；本机启动 12 秒保持运行（测试实例随后关闭）；
- `(Get-Item exe).VersionInfo` 正确返回：FileDescription/ProductName=`Starlight Launcher`、CompanyName=`Dream Wings Indie Dev Team`、LegalCopyright=`Copyright (C) 2026 Dream Wings Indie Dev Team`、FileVersion/ProductVersion=`1.0.0.0`（全部来自 metadata.txt）；
- 资源目录：RT_ICON、RT_GROUP_ICON、RT_VERSION 三类资源均在。

## 五、重建与验证结果

- 执行 `build-single-exe.bat` 完整打包（gluonfx:compile → native-image → gluonfx:link，约 8-10 分钟）；
- 产物：`target\gluonfx\x86_64-windows\Starlight Launcher.exe`；
- 本机实测：Start-Process 启动后进程持续存活，界面正常（测试后已关闭测试实例）；
- 注意：exe 的图标为项目原生图标；文件版本信息不再通过 rcedit 写入（native-image exe 不强制需要，版本号由启动器内 `AppConfig.APP_VERSION` 维护）。

## 六、“所有 Windows 设备”兼容说明

- **本 exe（x86_64）**：兼容 AMD64 的 Windows 7/8/10/11 及 Windows Server；不自带第三方 DLL，无需安装 VC++ 运行库即可运行（运行库缺失时 Windows 会提示而非拒绝）。
- **ARM64 Windows**（如 Windows on ARM 设备/苹果 M 系列虚拟机）：AMD64 exe 无法运行，需在 ARM64 环境用 `aarch64-windows` 目标另行构建，或使用下方 JAR 方式。
- **任意架构兜底（JAR 方式）**：`mvn package -DskipTests` 生成 fat JAR，配合已装的 JDK17 用 `java -jar target\starlight-launcher-cli-1.0.0-jar-with-dependencies.jar` 运行（启动器自带 Java 检测与自动安装）。
