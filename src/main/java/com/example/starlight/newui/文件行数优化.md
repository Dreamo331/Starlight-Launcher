想让 `LauncherView.java` 行数变少，**不要靠删空行、合并语句、删注释**，那只是把代码变难维护。真正有效的是：**拆类、抽服务、数据驱动 UI、把静态布局交给 FXML/CSS、消除重复代码**。

你这个文件已经把“页面构建 + 业务逻辑 + 弹窗 + 下载 + 社区 + 联机 + 设置 + 帧生成”全塞在一起了。目标应该是：

> `LauncherView` 只保留窗口壳、导航、页面注册、生命周期；  
> 其它全部拆成独立类。

private final Map<String, Supplier<Node>> pages = new LinkedHashMap<>();

private void switchToPage(String key) {
    Supplier<Node> supplier = pages.get(key);
    Node page = supplier != null ? supplier.get() : new Label("页面开发中: " + key);

## 6. 设置页用“数据驱动”生成

`buildAdvancedPage`、`buildJvmPage`、`buildGameDirPage` 这类页面大量重复：

```java
CheckBox toggle = createToggle(...);
toggle.setOnAction(e -> {
    configCache.put("Key", String.valueOf(toggle.isSelected()));
    saveConfig();
    showToast("xxx: " + ...);
});
root.getChildren().add(createSettingsCard("标题", "说明", toggle));
```

可以定义：

```java
record ToggleSetting(String title, String desc, String key, boolean def) {}

List<ToggleSetting> toggles = List.of(
    new ToggleSetting("全屏模式", "以全屏模式启动游戏", "Fullscreen", false),
    new ToggleSetting("版本隔离", "每个版本使用独立的游戏目录", "VersionIsolation", false),
    new ToggleSetting("主页快速进入存档", "在主页显示存档列表", "HomeQuickLaunchSave", false)
);

for (ToggleSetting s : toggles) {
    CheckBox toggle = createToggle(boolConfig(s.key(), s.def()));
    toggle.setOnAction(e -> {
        configCache.put(s.key(), String.valueOf(toggle.isSelected()));
        saveConfig();
    });
    root.getChildren().add(createSettingsCard(s.title(), s.desc(), toggle));
}
```

滑块、输入框、下拉框也可以类似封装：

```java
createSliderSetting(...)
createTextSetting(...)
createComboSetting(...)
```

高级设置页能少几百行。

## 7. 把 `setStyle` 大量移到 CSS

你文件里到处都是：

```java
label.setStyle("-fx-font-size: 14px; -fx-font-weight: 600; -fx-text-fill: #22c55e;");
```

改成：

```java
label.getStyleClass().add("text-success-bold");
```

CSS 里：

```css
.text-success-bold {
    -fx-font-size: 14px;
    -fx-font-weight: 600;
    -fx-text-fill: #22c55e;
}
```

动态颜色用 `PseudoClass` 或 CSS 变量。  
这一项能减少大量行数，而且主题切换更统一。

## 8. 匿名类改 lambda / 工具方法

你有很多：

```java
new UIGeneralControlClass.ResultCallback<Boolean>() {
    @Override
    public void onSuccess(Boolean result) { ... }

    @Override
    public void onError(String error) { ... }
}
```

如果 `ResultCallback` 不能改成函数式接口，可以写一个适配器：

```java
public final class Callbacks {
    public static <T> ResultCallback<T> of(Consumer<T> onSuccess, Consumer<String> onError) {
        return new ResultCallback<>() {
            @Override public void onSuccess(T result) { onSuccess.accept(result); }
            @Override public void onError(String error) { onError.accept(error); }
        };
    }
}
```

然后：

```java
UIGeneralControlClass.installLoaderAsync(..., Callbacks.of(
    ok -> { ... },
    err -> { ... }
));
```

也能减少不少行。

## 10. 用 `LauncherContext` 解耦

拆出去的页面类不要直接依赖 `LauncherView`，否则会循环依赖。定义：

```java
public interface LauncherContext {
    Stage stage();
    StackPane rootPane();
    Map<String, String> config();
    void saveConfig();
    void showToast(String msg);
    void switchToPage(String key);
    void showModalPanel(String title, Node content, double w, double h);
    void closeModalPanel();
    ExecutorService executor();
}
```

`LauncherView implements LauncherContext`，各页面构造器接收 `LauncherContext`：

```java
public class HomePage {
    private final LauncherContext ctx;

    public HomePage(LauncherContext ctx) {
        this.ctx = ctx;
    }

    public Node build() { ... }
}
```

这样拆类不会拆出循环依赖。

## 11. 推荐拆分顺序

从低风险到高风险：

1. 工具方法 → `UiUtils`、`StringUtils`、`VersionUtils`
2. Toast / Modal / Confirm / Input → `UiService`
3. 图标 / 头像 / 骨架屏 → `IconService`、`AvatarService`、`SkeletonFactory`
4. 下载任务 → `DownloadTaskManager`、`DownloadTaskCard`
5. 远程缓存 → `RemoteCacheService`
6. 各个页面 → `HomePage`、`DownloadPage`、`SettingsPage` 等
7. 业务逻辑 → `InstallService`、`CommunityService`、`SlanService`
8. 主类只留导航、页面注册、生命周期

## 12. 预计效果

当前文件大概几千行。按上面拆：

- `LauncherView` 可以降到 **300~500 行**
- 总行数可能减少 **20%~40%**，因为消除了重复代码
- 可维护性、可测试性大幅提升
- 单文件不再承担所有职责

## 13. 不要做的事

- 不要为了行数把多个语句塞到一行
- 不要删注释和空行
- 不要把所有东西都塞进一个 `Utils` 类
- 不要用继承链硬拆，优先组合
- 不要一次全改，按模块逐步迁移

> **把 `LauncherView` 从“上帝类”改成“壳 + 路由 + 上下文”，把页面、弹窗、下载、社区、联机、设置、帧生成全部拆成独立类；再用 FXML/CSS 和数据驱动减少重复 UI 代码。**

> **Ai优化建议：Refactor only, minimal unified diff, preserve behavior, extract class, no new dependencies, Java 17, keep public API, no formatting noise, output patch only, minimize tokens, maximize code quality, fast incremental changes. 每次只改一个模块，优先抽 UiService、DownloadTaskManager、IconService、SkeletonFactory、RemoteCacheService，再抽各 page 类；禁止整文件重写，只输出 diff/patch，不解释，改完保证编译通过。目标：LauncherView.java 降到 300～500 行，行为不变，可维护性提升。最后要保证UI样式什么的不变**
